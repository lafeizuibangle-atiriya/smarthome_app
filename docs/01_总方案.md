## 一、项目定位

做一个仿米家的鸿蒙智慧家居 App，5 个底部 Tab，覆盖「设备管理 + 智能场景 + 产品库 + 商城 + 个人中心」的完整闭环。

三条必须坚持的原则：

1. **设备是模拟的**：设备数据全部存在 MySQL 里，用户在 App 上控制 = 后端改数据库状态；环境监测数值（温湿度/空气质量/CO₂/烟雾/燃气）由后端定时任务每 30 秒随机波动，制造"真实设备"的错觉。
2. **购买是模拟的**：商城有真实的下单/订单流程和库存扣减，但"支付"按钮点击后直接把订单状态改成"已支付"，不接任何支付 SDK。
3. **前后端彻底分开**：前端只通过 HTTP 接口取数据，仓库分两个目录，靠接口文档对齐，可以并行开发。

### 与米家的功能对照（做到什么程度）

| 米家功能 | 本项目 | 实现程度 |
|----------|--------|----------|
| 主页设备卡片与房间切换 | ✅ | 房间 Tab + 设备卡片网格 + 环境数据卡 |
| 设备控制（开关/亮度/温度） | ✅ | 开关按钮、Slider 滑杆，状态存 JSON |
| 智能场景（一键执行/自动化） | ✅ | 手动场景一键执行；自动化做定时触发 |
| 产品库（了解生态产品） | ✅ | 产品列表 + 产品详情（参数、卖点、支持联动） |
| 商城（浏览/加购/下单/订单） | ✅ | 完整模拟流程，含购物车与订单列表 |
| 我的（登录态差异） | ✅ | 未登录置灰引导，登录后显示昵称与数据统计 |
| 真实的设备接入 / 语音助手 / 消息推送 | ❌ | 超出 Demo 范围，不做 |

## 三、整体架构（前后端分离）

```
┌──────────────────────────────────────────────┐
│  鸿蒙 App（ArkTS / ArkUI）                    │
│  pages 页面层 → view 组件层 → api 接口层       │
│                    ↓                          │
│              HttpClient 统一网络层            │
└──────────────────┬───────────────────────────┘
                   │ HTTP + JSON（统一 Result 结构）
                   │ header: token 鉴权
┌──────────────────▼───────────────────────────┐
│  Spring Boot 后端                             │
│  控制层 Controller  ← 只做参数接收与返回       │
│  业务层 Service     ← 业务规则、事务、权限      │
│  数据层 Mapper      ← MyBatis-Plus 数据读写     │
│  公共层 common      ← Result / 异常 / JWT      │
│  定时任务 task      ← 模拟全屋环境数值波动        │
└──────────────────┬───────────────────────────┘
                   │ MyBatis-Plus
              ┌────▼────┐
              │  MySQL  │
              └─────────┘
```

### 3.1 后端三层职责（本项目统一遵守）

| 层 | 职责 | 禁止 |
|----|------|------|
| 控制层 Controller | 接参数、取当前登录人、调 Service、包 `Result` | 写业务逻辑、直接调 Mapper |
| 业务层 Service | 业务规则、权限校验、事务、Entity↔VO 转换 | 写 SQL、碰 HttpServletRequest |
| 数据层 Mapper | 单表 CRUD、复杂查询 SQL | 写业务判断 |

## 四、数据库设计（12 张表）

### 4.1 用户与地址

```sql
user (id, username, password, nickname, avatar, create_time)
address (id, user_id, receiver, phone, region, detail, is_default)
```

### 4.2 设备侧（模拟设备）

```sql
room   (id, user_id, name, sort)
device (id, room_id, name, type, status, online, create_time)
       -- status 存 JSON：{"power":"on","brightness":80} / {"temperature":26.5,"humidity":60}
device_log (id, device_id, user_id, action, create_time)
scene      (id, user_id, name, icon, trigger_type, cron_expr, enabled)
             -- trigger_type: MANUAL 手动 / TIMER 定时(自动化)
scene_action (id, scene_id, device_id, action)   -- action 为 JSON，如 {"power":"on"}
```

### 4.3 产品库（只展示，不卖）

```sql
product (id, name, category, cover, slogan, description, specs, tags, related_goods_id)
        -- specs 存 JSON 规格参数数组；tags 存 "WiFi,联动"；related_goods_id 指向商城商品
product_category (id, name, sort)
```

### 4.4 商城（模拟购买）

```sql
goods_category (id, name, icon, sort)
goods         (id, category_id, name, cover, images, price, origin_price, stock,
               sales, detail, specs, status)
               -- images 存 JSON 数组（轮播图）；status: 1 上架 / 0 下架
cart_item     (id, user_id, goods_id, quantity, create_time)
orders        (id, order_no, user_id, address_id, total_amount, status, pay_time, create_time)
               -- status: 0 待付款 / 1 已付款 / 2 已完成 / 3 已取消
order_item    (id, order_id, goods_id, goods_name, goods_cover, price, quantity)
```

**设计要点**

- 订单项要**冗余商品名与图片快照**（`goods_name`、`goods_cover`），否则商品下架/改价后订单显示会出错。
- 金额统一用 `DECIMAL(10,2)`，不要用 float。
- 设备状态、商品图集、规格参数统一用 **JSON 字符串**字段，避免为每种类型建表。
- 所有业务表都带 `user_id`（或通过 `room_id` 间接归属），接口按当前登录人过滤，实现数据隔离。

以下 16 条都是真的踩过的坑，每一条都至少浪费过半小时。**动手前先读完，能省一整晚。**

| # | 红线 | 一句话后果 |
|---|------|-----------|
| 1 | 目录、文件名只用下划线 `_`，不用连字符 `-` | 电脑上会出现两套目录，改代码改到"空的那套"，怎么改都不生效 |
| 2 | 改代码/配置**先 Ctrl+S 保存到磁盘**，再谈重新启动 | IDEA / DevEco 标签页上有 `*` 号说明**没保存**，进程读到的还是旧文件 |
| 3 | 后端改完 `application.yml` 必须 **Rebuild（Ctrl+F9）** | 运行期读的是 `target/classes/application.yml`，不是 `src` 里的那份 |
| 4 | 后端**只允许启动一个实例** | 定时任务跑两份，环境数值双倍跳、场景重复执行 |

| 6 | 一次只改一个文件，改完**核对落盘**再改下一个 | 同时改多个文件时后发的改动会覆盖先发的，改动会"凭空消失" |

| 8 | 接口字段改了**先改文档再改代码**，并同步群里 | 前端按旧字段写，联调时两端互相甩锅 |
| 9 | `catch` 兜底**不要静默 `return null`** | 会把 `ClassCastException` 这类代码 bug 一起吞掉，变成"功能静默失效"，一行日志都没有，极难查 |
| 10 | Tab 子页面**不自带刷新**，要接刷新信号 | 登录后 UI 不变、列表不更新，看着像接口问题其实是页面复用没重读数据 |
| 11 | 后端改了 `.java` / `.yml`，**必须重启进程**（不只是 Build） | JVM 只加载一次 class，只 Build 不重启，跑的还是旧代码。这是本项目**第一高频**的"改了没用"（踩坑 12） |
| 12 | 轮询里的操作**不许无条件弹提示、写本地存储** | 每 5 秒弹一次、写一次 Preferences，提示变弹幕还白耗性能（踩坑 13） |
| 13 | 需要登录的接口，**未登录时不要请求、不要轮询** | 未登录时的 401 是预期行为，当成"过期"处理等于自己制造报错 |
| 14 | **ForEach 的 key 必须包含"会变的数据"**，不能只用 id | key 不变框架就复用旧组件不同步新数据，轮询拿到新状态也刷不上屏（踩坑 14） |

## 十一、实战踩坑记录（16 条，项目落地阶段补充）

> 这一章是**方案之外**的部分：前面十章是"应该怎么做"，这一章是"我们实际怎么踩的"。
> 建议全组通读一遍，尤其是**第 1、2、3、12 条**——
> 它们都表现为"改了没用"，但原因完全不同（目录找错 / 没保存 / 构建产物 / 进程没重启）。

### 踩坑 1：命名不一致，电脑上长出两套目录

**现象**：改完代码重启，行为完全没变；或者 `cd` 进目录发现里面是空的。

**原因**：方案文档里写的是 `smarthome-app` / `smarthome-server`（连字符），
实际用 DevEco / IDEA 新建工程时用的是 `smarthome_app` / `smarthome_server`（下划线）。
结果就是**同一个项目根目录下两套目录并存**，一套有代码、一套是空壳。

**排查**（在项目根执行，对比两个名字的目录都在不在）：

```cmd
dir /b D:\Code\smarthome_project
```

**解决**：确认有代码的那一套作为唯一工程；多余目录删掉；
但**先确认 Maven Wrapper 有没有被一起删掉**——`mvnw`、`mvnw.cmd`、`.mvn/` 是命令行启动后端用的，
早期就因为它们待在要被删的目录里，删完发现 `mvnw.cmd` 不见了。

**纪律**：命名只用 `_`，方案、文档、代码、命令行**四处写法必须完全一致**。

### 踩坑 2：改了配置文件，启动却读的还是旧的

**现象**：`application.yml` 里明明改成 `password: "123456"`，启动日志还是
`Access denied for user 'root'@'localhost' (using password: YES)`。

**两个原因叠在一起，必须分别排除**：

**原因 A —— 编辑器没落盘。** 在 IDEA 里改完，标签页标题上会有一个 `*`，
表示**改动只在编辑器内存里，磁盘文件还是旧的**。进程启动读磁盘，自然读到旧值。

```cmd
:: 用命令行直接看磁盘上的真实内容，别信编辑器
type D:\Code\smarthome_project\smarthome_server\src\main\resources\application.yml
```

**原因 B —— 运行期读的是 `target/classes/`。** Maven 会把 `src/main/resources/` 下的文件
**复制**到 `target/classes/`，Spring Boot 运行时读的是**副本**。
只改源文件不 Rebuild，副本还是旧的。

**解决顺序**（照这个顺序做，别跳步）：

1. 编辑器里改完 → `Ctrl+S` → 确认标签页 `*` 消失。
2. `type` 一下源文件，肉眼确认磁盘内容已变。
3. IDEA 里 `Build → Rebuild Project`（快捷键 `Ctrl+F9`），让 `target/classes/` 同步。
4. 再启动。

> 排查口诀：**先确认磁盘，再怀疑缓存。** 顺序反了会绕很久。

### 踩坑 3：`target/` 到底是什么，能不能删

`target/` 是 **Maven 的构建产物目录**，不是源码，可以随时删（删了重新 Rebuild 就会再生成）。

| 目录 | 内容 | 是否提交 Git |
|------|------|--------------|
| `src/main/java` | 你写的 Java 源码 | ✅ 必须提交 |
| `src/main/resources` | `application.yml`、SQL 等**源**配置 | ✅ 必须提交 |
| `target/classes` | 上面两者的**编译/复制副本**，运行时真正读的 | ❌ 不提交 |
| `target/*.jar` | 打包产物 | ❌ 不提交 |

**这解释了踩坑 2 的原因 B**，也解释了为什么"删了 `target` 重启又好了"——
删掉之后重新构建，副本自然是最新的。

### 踩坑 4：后端不能开两个

项目里有**三个**定时任务跑在**同一个进程内**：

- `SensorSimTask`：每 30 秒让温湿度数值波动一次；
- `SceneTimedTask`：每分钟扫描一次定时场景；
- `WaterTimedTask`（2026-09 新增）：每分钟扫描一次浇花水泵 —— 到点自动开泵、到点自动停泵并扣减水箱水量。

如果 IDEA 里点了一次运行、命令行又 `mvnw.cmd spring-boot:run` 起了一个（或端口没释放直接重启），
就会有**两个进程同时写库**：数值双倍跳动、定时场景重复执行、水泵水量双倍扣减。

**排查**：看 `Port 8080 was already in use`，或

```cmd
netstat -ano | findstr :8080
```

拿到 PID 后到任务管理器结束它。**同一时间只保留一个后端进程。**

### 踩坑 5：ArkTS 比 TypeScript 严格得多

从 Vue / 小程序 / 普通 TS 转过来的同学最容易在这里翻车。
同一段代码在那些地方能跑，在 ArkTS 里**直接编译失败**，一次能报 25 个 ERROR。

最常见的三类（完整正反例见《02_开发手册_前端.md》第 5.0 节）：

| 错误码 | 大白话 |
|--------|--------|
| `arkts-no-untyped-obj-literals` | 不能把裸的 `{ ... }` 直接当参数传，必须先声明 interface |
| `arkts-no-any-unknown` | 不许用 `any`，`ForEach` 的回调参数必须标类型 |
| `arkts-no-implicit-return-types` | 箭头函数不能隐式返回 Promise，得用 `{ }` 包住 |

**看报错的方法**：控制台末尾 `COMPILE RESULT:FAIL {ERROR:n WARN:m}`——
**只看 ERROR，WARN 不用管**（目前 129 条 WARN 全是 API 已废弃提示，不影响运行）。
先从**第一条 ERROR** 改，ArkTS 常常一个错级联出一串，改完第一条重新编译，数量往往直接归零。

### 踩坑 6：hvigor 报错"改了但没消失"

改好了代码，重新编译，报错还是那几条，甚至行号都对不上。

**原因**：hvigor 守护进程缓存了旧的文件快照。

**解决**：

- DevEco Studio 里：`Build → Clean Project`，然后重新编译；
- 命令行编译：末尾加 `--no-daemon`。

### 踩坑 7：导入 SQL 脚本时 PowerShell 报错

`mysql -u root -p < Mysql/init_all.sql` 在 **PowerShell 里会失败**——PowerShell 不支持 `<` 重定向。

三种可行写法，任选一种：

```cmd

cmd /c "mysql -u root -p --default-character-set=utf8mb4 < Mysql\init_all.sql"

:: 2) 进入 mysql 后用 source
mysql -u root -p

:: 3) 直接用 Navicat「运行 SQL 文件」（图形界面，最省事）
```

> `init_all.sql` 里自带建库语句（`DROP DATABASE IF EXISTS` + `CREATE DATABASE`），
> 不用手动新建库，也不用先 `USE`。看到 `Unknown database 'smart_home'` 说明脚本根本没跑进去。
>
> ⚠️ 这份脚本是**单一自包含版本**（建库 + 建表 + 演示数据），没有任何"分段互斥"的坑，
> **直接执行整个文件即可**，也可以反复执行（每次都回到同一套干净演示数据）。详见 `04_数据库设计.md` 第六章。

### 踩坑 7.1：SQL 文件里的中文变成问号或乱码

如果导入后中文全变成 `??` 或乱码，多半是**文件编码不是 UTF-8**，或导入时客户端字符集不对。
正确做法：

```cmd
:: 导入时显式指定字符集
mysql -u root --default-character-set=utf8mb4 -e "source D:/Code/smarthome_project/Mysql/init_all.sql"
```

> 变成"双重编码"的乱码（表现是 `用法` 变成 `鐢ㄦ硶` 这种）。改 SQL 文件优先用编辑器（VS Code / Notepad++）
> 另存为 UTF-8，或改用 Python 脚本读写。

### 踩坑 8：启动日志一大片红色，不知道看哪行

Spring Boot 启动失败会打几十行以 `at org.springframework...` 开头的**调用栈**，
它们全是"路过"的函数名，**不是错误原因**。

**只看两处**：

1. 第一行 `ERROR` —— 谁抛的；
2. **`Caused by:`** —— 真正的原因，通常只有一行，而且写得非常清楚。

```
Caused by: java.sql.SQLException: Access denied for user 'root'@'localhost' (using password: YES)
                                    ↑ 看到这句就直接去查密码，不用往下看了
```

**另有一个反直觉的点**：日志出现 `Started SmartHomeApplication in 3.2 seconds` **不代表数据库连上了**。
连接池是**懒加载**的，要等第一个请求进来才真正建连接。
所以「启动成功但接口报 500」是很正常的组合，往上翻找 `Caused by` 才是正解。

### 踩坑 9：一次改多个文件，改动"凭空消失"

这条主要是多人协作 / 用工具批量改代码时踩到的。

**现象**：明明改了 A 文件和 B 文件，重新编译发现 A 的改动没了。

**原因**：对**同一个文件**并发发起多次修改，后一次基于"旧内容"的快照覆盖了前一次的改动。

**纪律**：

- **一次只改一个文件**，改完拉开文件确认内容真的写进去了（用搜索或 `type` 核对关键字）；
- 同一文件要改多处时，**串行做**，不要并发；
- 改完一批后**统一编译一次**，别等攒到最后。

### 踩坑 10：登录接口返回 200 和 token，但所有需要登录的接口全部 401

**现象**：App 上点登录 → 弹出「登录成功」→ 但页面还是未登录；
或者刚登录完，随便点个需要登录的功能就提示「登录已过期，请重新登录」。

**关键疑点澄清**：这个现象的直觉反应是"请求没发到后端"，**但这次不是**。
用 curl 直接打后端，登录接口返回了 `{"code":200,"data":"eyJ0eXAi..."}`，token 生成得好好的：
**后端收到了请求、也成功登录了，问题出在"这个 token 之后不被承认"。**

**根因**：`common/JwtUtil.java` 的 `verifyToken` 里这一行——

```java
Integer userId = (Integer) JWT.of(token).getPayload("userId");
```

Hutool 5.8.x 把 JSON 数字解析成 `cn.hutool.core.convert.NumberWithFormat`
（`Number` 的子类，**不是** `Integer`），所以这里抛 `ClassCastException`：

```
NumberWithFormat cannot be cast to java.lang.Integer
```

而这个异常**正好被同一个方法里的 `catch (Exception e)` 吞掉**，方法安静地返回 `null`，
拦截器据此判定"未登录"→ 返回 401。**控制台一行报错都没有**——
因为异常在业务代码内部被自己 catch 了，根本没往上抛。

**顺带查出的第二个问题**：Hutool 的 `JWT.verify()` **只校验签名，不校验 `exp` 有效期**。
实测手工造一个昨天过期的 token，`verify()` 依然返回 `true`——过期 token 能一路通过。

**修复**（两处一起改，见后端手册 2.4 节）：

```java
JWT jwt = JWT.of(token).setKey(SECRET.getBytes());
if (!jwt.validate(0)) return null;              // ① 签名 + 有效期，替代 verify()
Object raw = jwt.getPayload("userId");
if (raw instanceof Number) return ((Number) raw).longValue();   // ② 先转 Number 再取 long
```

**为什么这个坑值得单独记一条**：

| 反直觉的地方 | 说明 |
|--------------|------|
| 登录"成功"了 | 登录接口本身完全正常，所以不会怀疑后端 |
| 报错被吞了 | `catch (Exception e) { return null; }` 把代码 bug 一起吞了，日志干净得像没问题 |
| 表现像网络问题 | 401 会让前端清掉本地 token，看起来就像"根本没登上去" |
| 权限模型没报错 | 拦截器的判断逻辑本身没错，错的是它拿到的输入永远是 `null` |

**通用教训**（比这个 bug 本身更重要）：

> 写 `catch (Exception e) { return null; }` 这类"安全兜底"时，
> 它会把 `ClassCastException` / `NullPointerException` 这类**代码 bug** 一起吃掉，
> 让"功能静默失效"取代"直接报错"。**要么至少 `e.printStackTrace()`，要么记一条日志。**
> 宁可吵，不要静默。

### 踩坑 11：登录成功后，Tab 页还是显示未登录

**现象**：踩坑 10 修完之后，后端 401 已经没有了，但 App 上「登录成功」提示弹出后，
「我的」页**依然是"登录 / 注册"**，必须杀进程重开才显示已登录。

**根因**：`Tabs` 内嵌的 5 个 Tab 页是 `@Component`，**不是 `@Entry` 页面**，于是——

| 你以为 | 实际 |
|--------|------|
| 子页面有 `onPageShow`，返回时自动刷新 | ❌ `onPageShow` 是 `@Entry` 专有，`@Component` 没有 |
| `aboutToAppear` 每次切回来都跑 | ❌ 只在组件**首次创建**时跑一次 |
| 登录成功后 UI 自然变已登录 | ❌ `@State isLogin` 还是登录前的 `false`，没人去重新读 |

`LoginPage` 执行 `router.back()` 回到 `Index` 时，`MinePage` 组件是**复用**的，
它的 `refresh()` 根本不会被调用。

**修复**：由 `@Entry` 的 `Index` 统一广播刷新信号，需要感知"页面重新可见"的子组件接信号。

> 📄 **文件**：`smarthome_app/entry/src/main/ets/pages/Index.ets` ｜ **负责人**：C（前端框架）

```typescript
// smarthome_app/entry/src/main/ets/pages/Index.ets（@Entry）
@State refreshTick: number = 0
aboutToAppear() {
  // init 是异步的，读完再广播，否则重启后登录态会被判成未登录
  TokenStore.init().then(() => { this.refreshTick++ })
}
onPageShow() {              // router.back() 回到本页时触发
  this.refreshTick++
}
// build 里
TabContent() { MinePage({ refreshTick: this.refreshTick }) }
// onChange 里
this.currentIndex = index
this.refreshTick++          // 切 Tab 也刷新

// MinePage.ets（@Component）
@Prop @Watch('onRefreshTick') refreshTick: number = 0
onRefreshTick() { this.refresh() }
```

**谁需要接这个信号**：显示**登录态**或**会变化的列表**的 Tab 页。

**判断口诀**：Tab 页里的数据"第一次进来是对的、后来就不对了"，
基本就是这个坑，而不是接口的问题。

> ⚠️ **修正**：早期版本这里写过"首页 HomePage 不用接，它本来就有 5 秒轮询，自己会刷"。
> 后来发现这是错的 —— 正因为它无条件轮询，未登录时每 5 秒就撞一次 401，引发踩坑 13。
> 现在 **HomePage、SmartPage、MinePage 三个都接了** `refreshTick`。

### 踩坑 12：代码改对了、编译也过了，接口行为却没变（后端）

**现象**：`JwtUtil` 修完、编译通过、单测也过了，App 一登录还是老样子。
一度以为是"还有第二个 bug"，其实是**跑着的进程里还是旧 class**。

**根因**：**JVM 只在启动那一刻加载 class**，之后不会去磁盘看源文件变没变。
Rebuild（Ctrl+F9）只是把新 class 写进 `target/classes/`，
**不会**装进已经跑起来的进程。

**判断方法**：比对「进程启动时间」和「class 编译时间」，**进程比 class 早就是旧的**。

```powershell
Get-CimInstance Win32_Process -Filter "Name = 'java.exe'" | Select-Object ProcessId, CreationDate
Get-Item .\target\classes\com\smarthome\common\JwtUtil.class | Select-Object LastWriteTime
# 本例：进程 15:26 启动，class 15:46 编译 → 差 20 分钟，铁证
```

**修复**：IDEA 里点 **⟳ Rerun**（或先 Stop 再 Run）—— 不是只点 Build。

| 操作 | 生效吗 |
|------|--------|
| ⟳ Rerun / Stop → Run | ✅ |
| 只 Build / Ctrl+F9 | ⚠️ 只更新 `target/classes/`，进程里还是旧 class |
| 只重开模拟器/App | ❌ 后端根本没动 |

**推广到整个后端**：任何 `.java` 改动、`application.yml` 改动、`@Scheduled` 的 cron 改动，
**都要重启进程**。前端同理 —— 只 Build 不 Run，手机上的 hap 还是旧的。

**教训**：这种"明明改了"的问题，**第一步永远是确认运行中的东西是不是新的**，
而不是回去怀疑刚写的那几行代码。

### 踩坑 13：401 提示变成"弹幕"，还白白耗性能（前端）

**现象**：token 失效后，App 每几秒就弹一次"登录已过期，请重新登录"，
而且明显感觉卡、耗电。未登录进首页/智能页时也会一直弹。

**根因**（两个叠加）：

1. **提示没节流**。首页有 5 秒轮询，每个轮询周期都会拿到 401，
   而 `HttpClient` 在 401 分支里**无条件** `showToast` →
   提示变成弹幕，5 秒一条。
2. **清理动作重复执行**。同一个分支里还无条件调了 `TokenStore.clear()`，
   而它内部是 `delete` + `flush`，**是真实的磁盘 I/O** —— 每 5 秒写一次本地存储。
3. **未登录也去请求需要登录的接口**。首页/智能页一进来就拉数据，
   未登录时这些 401 是**预期行为**，却被当成"过期"处理，等于自己制造报错。

**修复三条**（详见前端手册 4.3.1）：

| 纪律 | 做法 |
|------|------|
| 只在"本地本来带 token"时才算过期 | `const hadToken = TokenStore.isLogin(); if (!hadToken) return`<br>注意这句必须写在 `await TokenStore.clear()` **之前** |
| 基础设施类提示节流 | 同一条文案 10 秒内只弹一次（`Map<文案, 时间戳>`） |
| 未登录不发需登录的请求 | 页面先判 `TokenStore.isLogin()`，未登录只渲染引导，**不请求、不起轮询** |

**顺手修的性能问题**：`Tabs` 的子页切走后**不销毁**，`setInterval` 会一直跑。
停在"商城"页时首页还在后台每 5 秒发一次请求。
现在由 `Index` 给 `HomePage` 传 `visible = (currentIndex === 0)`，切走就 `stopPolling()`。
轮询里还加了"上一轮没回来就跳过"的防重入，避免网络慢时请求堆积。

**设计原则**（比代码更重要）：

> **"后台自动触发"的提示要克制，"用户主动操作"的提示要明确。**
>
> - 401 / 网络异常 / 服务异常 → 会在后台反复出现 → **必须节流**
> - 400 业务错误（"库存不足""用户名已存在"）→ 用户点了按钮才出现 → **不节流，每次都要说清楚**

**教训**：加了轮询之后，**任何"每次请求都会执行"的副作用都要重新审一遍** ——
提示、写本地存储、发通知，全都可能从"偶尔一次"变成"每 5 秒一次"。

### 踩坑 14：轮询明明在跑、后端数据也在变，界面就是不刷新（前端）

**现象**：首页"室内环境"主卡的数值会动，但下面的**设备卡片状态永远不动**；
（当时还有个温湿度计详情页，它的大数字也永远停在进页面那一刻。）

**先排除后端**：间隔 35 秒直接 curl 两次 `/api/home/overview`，
发现环境数值真的在变（`26.4℃/53% → 26.2℃/54%`）—— 数据是活的，问题在前端。

**根因**：**ForEach 的 key 只用了 `device.id`**。

ArkUI 的 ForEach 重新渲染时会对比前后两组 key：
**key 相同 → 认为这条数据没变 → 直接复用旧组件，不把新数据同步给它的 `@Prop`**。
所以轮询拿到的最新 `status` 根本没进卡片，卡片上永远是最初那次的数据。
而顶部环境主卡是普通 `@State` 直接绑在 `Text` 上，整体赋值就会刷新 ——
**同一个页面一半动一半不动**，特别迷惑人。

**修复**：把会变的字段拼进 key，数据一变 key 就变，组件用新数据重建：

> 📄 **文件**：`smarthome_app/entry/src/main/ets/pages/home/HomePage.ets` ｜ **负责人**：D（前端页面）

```typescript
// ❌ 只用 id：状态变了 key 不变，界面永不刷新
(device: Device) => device.id.toString()

// ✅ 拼上会变的字段
(device: Device) => `${device.id}_${device.name}_${device.online}_${JSON.stringify(device.status)}`

// ✅ 环境面板的指标格同理：每个数值都会变，都要参与 key
(cell: EnvMetricCell) => `${cell.key}_${cell.value}_${cell.level}`
```

同一类问题一次性全修了：智能页场景（拼 `enabled`）、订单列表（拼 `status`，
否则取消订单后状态文字不变）、房间管理（拼 `name`）、商城商品（拼 `stock`/`sales`）、
**环境监测面板（拼各指标数值与等级文案）**。

**顺手补的另一半**：设备**详情页**之前只在进入时拉一次数据，
停在那里看大数字永远不会动 —— 补了 5 秒轮询
（拖滑杆时用 `SliderChangeMode` 暂停覆盖，防止滑杆被服务端值"拽走"）。

**教训**：`ForEach` 的 key 不是"能区分就行"，它还承担着
**"告诉框架这条数据变没变"** 的职责。列表数据里任何会变的展示字段，都要参与 key。

### 踩坑 15：拿"还没实现的接口"做健康检查，看着像后端崩了

项目早期验证"后端起没起来"，很多人顺手敲文档里的
`curl http://localhost:8080/api/product/categories`，结果拿到：

```json
{ "code": 500, "msg": "服务器繁忙，请稍后再试", "data": null }
```

于是开始怀疑依赖、怀疑数据库、怀疑 yml …… 其实后端**完全正常**。

**原因**：当时产品库还是骨架里的空壳（`ProductController` 里一个端点都没有）。
请求路径没人处理时，Spring 会抛 `NoResourceFoundException`，它被
`GlobalExceptionHandler` 里兜底的 `@ExceptionHandler(Exception.class)` 接住 → 统一返回 500。

> 产品库后来已经实现（`/api/product/**` 三个端点都可用），但**这条教训至今有效**：
> 只要打的是一个**不存在的路径**，返回值就是 `500` 而不是 `404`。

**教训**：

1. 健康检查只能用**需要登录的接口**（推荐 `/api/user/info`），这样"能连上"和"没连上"一眼可分：

   ```cmd
   curl http://localhost:8080/api/user/info
   :: {"code":401,"msg":"请先登录"}
   ```

   拿到 `401` 才算成功 —— 它同时证明了三件事：**服务已启动**、**拦截器已生效**、**中文没乱码**。

2. **打任何不存在的路径都会得到 `500` 而不是 `404`**。
   看到 500 先问一句"这个接口是不是还没写/路径写错了"，再去翻后端日志里的 `系统异常` 堆栈，
   不要一上来就怀疑环境。

3. 想让报错更准确，可以在 `GlobalExceptionHandler` 里补一段
   （属于公共层改动，改前在群里说一声）：

   ```java
   /** 路径没匹配到任何 Controller —— 多半是这个接口还没写，别报 500 吓人 */
   @ExceptionHandler(NoResourceFoundException.class)
   public Result<Void> handleNotFound(NoResourceFoundException e) {
       log.warn("[接口不存在] {}", e.getResourcePath());
       return Result.error(404, "接口不存在（可能尚未实现）");
   }
   ```

### 踩坑 16：`promptAction` 忘了 import，报 `Cannot find name 'promptAction'`

**现象**：照着手册抄页面，`router` 导了，`promptAction.showToast(...)` 也写了，
编译却停在 `Cannot find name 'promptAction'`。

**原因**：ArkTS 不做全局注入。`router` / `promptAction` 都来自 `@kit.ArkUI`，
用到谁就必须显式 import 谁 —— 不像某些前端框架会把 toast 挂在全局对象上。

```typescript
// ❌ 只导了 router，但下面用了 promptAction
import { router } from '@kit.ArkUI'

// ✅ 两个都导
import { router, promptAction } from '@kit.ArkUI'
```

**教训**："`Cannot find name 'xxx'`" 这类报错，**九成是 import 漏了**，
不需要去查 API 是否存在。先把用到的名字和 import 列表对一遍。
