# 智慧家居 App 部署手册

| 项 | 内容 |
|---|---|
| 适用版本 | v1.0（2026-11-23） |
| 部署形态 | 方式一：Docker Compose 一键部署（推荐）；方式二：本机手动部署（开发调试用） |

## 1. 方式一：Docker Compose 一键部署（推荐）

### 1.1 环境要求

| 软件 | 版本要求 | 说明 |
|---|---|---|
| Docker Desktop（Windows/Mac）或 Docker Engine（Linux） | Docker 24+，Compose v2 | Windows 需开启 WSL2 |
| 可用内存 | ≥ 4 GB | MySQL + App + 监控共约 1.5 GB |
| 端口 | 8080 / 3306 / 6379 / 9090 / 3000 未被占用 | 主机已有 MySQL 时见 1.4 排错第 1 条 |

### 1.2 部署步骤

```bash
cd smarthome_project

# 1. 启动全部（含监控）：MySQL 首次启动自动执行 Mysql/init_all.sql 建库灌演示数据
docker compose up -d

# 2. 查看启动状态（等 app 变 healthy，约 1~2 分钟）
docker compose ps

# 3. 验证
curl http://localhost:8080/actuator/health          # {"status":"UP"}
curl -X POST http://localhost:8080/api/user/login \
     -H "Content-Type: application/json" \
     -d '{"username":"demo","password":"123456"}'   # 返回 token
```

| 服务 | 地址 | 说明 |
|---|---|---|
| 后端 App | http://localhost:8080 | App 端连接这个地址 |
| MySQL | localhost:3306（root/123456，库 smart_home） | 数据存 docker 卷 mysql_data |
| Redis | localhost:6379 | 验证码 + 订单幂等 |
| Prometheus | http://localhost:9090 | 指标抓取 |
| Grafana | http://localhost:3000 | admin/admin，见 1.3 |

只起核心三个（不搭监控）：`docker compose up -d mysql redis app`。

### 1.3 Grafana 基础监控面板

1. 浏览器打开 http://localhost:3000，admin/admin 登录；
2. Connections → Data sources → Add → 选 Prometheus，URL 填 `http://prometheus:9090`（compose 网络服务名），Save & Test；
3. 导入 JVM 面板：Dashboards → Import → 填面板 ID **4701**（Spring Boot 2.x/3.x 统计）或 **19004**（Spring Boot API），数据源选刚建的 Prometheus，Import；
4. 能看到：JVM 内存/GC、HTTP 请求速率与耗时分布（按 uri 维度）、HikariCP 连接池活跃数——压测时打开对比效果直观。

### 1.4 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| mysql 起不来，报端口绑定失败 | 主机 3306 已被本地 MySQL 占用 | compose 里 mysql 端口改 `"3307:3306"`，app 环境变量加 `DB_HOST: mysql` 不变（容器内互访不受影响），App/本机工具连 3307 |
| app 反复重启 | MySQL 未就绪或密码不符 | `docker compose logs app` 看日志；确认 depends_on 健康检查通过 |
| 登录接口报"系统异常" | Redis 没起 | `docker compose ps` 确认 redis 状态；compose 默认已带 |
| 想清空数据重来 | 数据卷里有旧数据 | `docker compose down -v`（会删库），再 `up -d` 重新初始化 |
| 首次构建很慢 | Maven 拉依赖 | Dockerfile 已配阿里云镜像，首构建约 3~5 分钟，之后有缓存 |

## 2. 方式二：本机手动部署（开发调试）

前置：JDK 17、MySQL 8.0、Redis 已安装并启动。

```bash
# 1. 初始化数据库（可反复执行，回到同一套演示数据）
mysql -u root -p --default-character-set=utf8mb4 < Mysql/init_all.sql

# 2. 启动 Redis
# Windows：D:/Soft/Redis/redis-server.exe；Linux：systemctl start redis

# 3. 启动后端
cd smarthome_server
./mvnw spring-boot:run          # Windows 需先设 JAVA_HOME 指向 JDK 17

# 4. 前端：DevEco Studio 打开 smarthome_app，签名后运行到模拟器/真机
#    App 端服务器地址配置指向 http://<本机局域网IP>:8080
```

本机部署与容器部署的差异只有两点：数据库/Redis 地址（localhost vs 服务名）、进程管理（手动 vs compose）。配置已通过环境变量占位（`DB_HOST`/`REDIS_HOST`）实现同一份代码两种部署。

## 3. 应用配置说明（application.yml 关键项）

| 配置 | 默认值 | 环境变量覆盖 |
|---|---|---|
| 数据库地址 | localhost:3306/smart_home | `DB_HOST`、`DB_USER`、`DB_PASSWORD` |
| Redis 地址 | localhost:6379 | `REDIS_HOST` |
| 服务端口 | 8080 | `SERVER_PORT` |
| 华为云 IoT | enabled=true（实训箱联动） | 改 yml（涉及多字段，暂不做环境变量化） |

## 4. 数据备份与恢复

```bash
# 备份（容器部署）
docker exec smarthome-mysql sh -c 'exec mysqldump -uroot -p"123456" smart_home' > backup.sql

# 恢复
docker exec -i smarthome-mysql sh -c 'exec mysql -uroot -p"123456" smart_home' < backup.sql
```

## 5. 升级发布

```bash
# 改代码后重新构建镜像并滚动替换（数据卷不受影响）
docker compose build app
docker compose up -d app
```

## 6. 安全收尾清单（验收后执行）

1. 修改 MySQL root 密码（compose 的 `MYSQL_ROOT_PASSWORD` 与 `DB_PASSWORD` 同步改）；
2. 修改 demo 账号密码或禁用；
3. QQ 邮箱 SMTP 授权码与华为云 IAM 子用户密码（Smarthome@2026）在云控制台重置，同步更新 application.yml；
4. 生产环境建议：JWT 密钥外部化、HTTPS、数据库不映射 3306 到公网。
