# 智慧家居项目需求报告

> 项目名称：仿米家智慧家居 App（含真实硬件接入）
> 文档版本：v2.0（2026-11-20，按硬件接入后的最新形态编写）
> 适用场景：课程项目结项、答辩材料

---

## 一、项目背景

智能家居产品已进入普通家庭，但现有方案普遍存在两个痛点：一是不同品牌的设备各自为政，需要在多个 App 之间切换；二是多数课程类演示项目只停留在界面模拟，设备数据来自随机数，无法体现"物"的真实性。

本项目以米家 App 为交互范本，构建一套覆盖"移动端控制 — 云端接入 — 真实硬件执行"的完整智慧家居系统：用户在 HarmonyOS App 上查看与控制设备，指令经后端与华为云 IoT 平台下发到真实开发板，传感器数据实时回传到 App；同时保留商城、产品库等完整业务，展示一个智能家居产品从控制到购买的完整用户旅程。

## 二、项目目标

1. 实现一个界面与交互对齐米家风格的 HarmonyOS 原生 App，包含 5 个主 Tab 与约 20 个页面。
2. 设备数据来自真实硬件：温湿度、光照、人体感应、烟雾由传感器采集，灯、风扇、自动门、蜂鸣器为真实执行器。
3. 建立"云—管—边—端"完整链路：设备通过 MQTT 接入华为云 IoTDA，后端通过 AMQP 订阅属性上报，命令经华为云下发至设备，全链路秒级到达。
4. 支持自动/手动双模式：自动模式下设备按环境规则联动（光控灯、温控风扇、人体感应控门、烟雾报警），手动模式由用户完全掌控。
5. 完成商城模拟购买流程（浏览、加购、下单、支付、订单管理），形成完整业务闭环。

## 三、用户与使用场景

目标用户为普通家庭用户。核心使用场景如下：

| 编号 | 场景 | 描述 |
|---|---|---|
| S1 | 远程查看 | 用户在 App 首页查看各房间设备状态与实时环境数据（温度、湿度、光照），数据来自真实传感器 |
| S2 | 远程控制 | 用户点按设备卡片或进入详情页，控制灯的开关与亮度色温、风扇、自动门、蜂鸣器等 |
| S3 | 自动模式 | 用户开启自动模式后，天黑自动开客厅灯、室温超过 30℃ 自动开风扇、有人靠近自动开门，无需人工干预 |
| S4 | 安全报警 | 厨房烟雾传感器检测到烟雾时，无论何种模式立即触发蜂鸣器报警并开启风扇排烟 |
| S5 | 场景执行 | 用户一键执行"回家模式"等场景，多台设备按预设动作同时变化 |
| S6 | 选购商品 | 用户浏览产品库了解生态产品，进入商城完成加购、下单与模拟支付 |
| S7 | 账号管理 | 用户注册登录（支持邮箱验证码），维护收货地址与个人信息 |

## 四、功能需求

### 4.1 账号与安全

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR1.1 | 账号密码登录 | 登录成功返回 JWT，重启 App 保持登录态 | 高 |
| FR1.2 | 注册 | 账号密码注册，支持邮箱验证码校验 | 高 |
| FR1.3 | 鉴权拦截 | 除登录注册外全部接口要求 token，数据按用户隔离 | 高 |
| FR1.4 | 个人中心 | 昵称头像、设备数与订单数统计、退出登录 | 中 |

### 4.2 设备管理（核心）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR2.1 | 首页总览 | 一次请求返回房间、设备、环境数据与全屋模式，配合 1 秒轮询实现近实时刷新 | 高 |
| FR2.2 | 设备控制 | 控制指令经后端下发华为云（Light/Motor/Servo/Beep 等命令），设备执行后属性上报回写数据库，App 显示硬件真实状态 | 高 |
| FR2.3 | 房间管理 | 房间增删改；设备归属房间，按联动场景划分（客厅：灯/风扇/自动门/人体感应；阳台：环境检测；厨房：烟感/蜂鸣器） | 中 |
| FR2.4 | 操作记录 | 每次控制写入 device_log，设备详情页可查 | 中 |
| FR2.5 | 指令清洗 | 只读字段丢弃、数值越界拒绝、枚举白名单，安全边界在后端 | 高 |

### 4.3 环境监测与自动模式

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR3.1 | 实时环境数据 | 温度、湿度、光照由设备传感器采集，经华为云 AMQP 推送至后端入库，App 侧秒级可见 | 高 |
| FR3.2 | 自动/手动模式切换 | App 切换全屋模式，经后端下发 Mode_control 命令；设备端 KEY4 本地切换后，App 通过 ModeStatus 上报同步显示 | 高 |
| FR3.3 | 自动联动规则 | 光照≤10lx 开客厅灯、≥50lx 关灯；温度≥30℃ 开风扇、≤28℃ 关；人体感应到人开自动门、5 秒无人关门；联动逻辑在设备固件内实现 | 高 |
| FR3.4 | 烟雾报警 | 任何模式下，检测到烟雾立即蜂鸣器报警并开启风扇排烟（不动作自动门） | 高 |
| FR3.5 | 环境检测设备卡片 | App 展示环境检测设备的实时数值与在线状态 | 中 |

## 五、非功能需求

| 类别 | 需求 |
|---|---|
| 实时性 | 传感器变化到 App 可见全链路最坏延迟 2 秒内（设备上报完成即计时，周期 500ms；App 轮询 1 秒） |
| 安全性 | 密码 BCrypt 加盐存储；JWT 校验签名与有效期；控制指令后端白名单清洗；天气密钥不进入客户端 |
| 可靠性 | 设备掉线自动重连 MQTT；AMQP 断线重连；接口统一异常处理与错误码 |
| 数据一致性 | 设备状态以硬件上报为准（云平台数据回写数据库），避免界面与硬件不一致 |
| 可维护性 | 设备类型收敛为后端字典类；接口契约文档先行；SQL 收敛为单一自包含脚本 |

## 六、系统边界

- 商城支付为模拟流程（不接入真实支付渠道），下单后直接置为已付款。
- 空调、窗帘等部分设备类型为界面模拟设备（无对应硬件），状态存于数据库。
- 不做语音交互、不做消息推送（告警通过 App 轮询展示）、不做多家庭多用户共享。

## 七、验收标准

1. App 登录后首页能看到真实传感器数据，遮挡光敏传感器后客厅灯在自动模式下自动点亮。
2. App 点击灯开关，串口可见设备执行命令，约 1 秒后 App 状态与硬件一致。
3. App 切换自动/手动模式，串口输出模式切换日志，App 显示与硬件同步（含板上按键切换）。
4. 触发烟雾传感器，蜂鸣器响、风扇开启、App 立即显示报警状态。
5. 商城全流程（加购、下单、支付、订单）无报错，库存扣减正确。
6. 全流程演示 5 分钟无报错，设备端串口输出连续无卡顿。
