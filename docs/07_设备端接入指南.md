# 07 · 设备端接入指南（软件模拟 → BearPi 真板子）

> 面向本项目的设备端（南向）落地。目标：让"设备"产生真实数据并进入后端，
> 最终由 HarmonyOS App 看到。
>
> **重要结论先说**：本项目后端（`smarthome_server`）**没有引入 MQTT**，
> 设备和 App 共用同一套 REST 接口。所以设备端一律走 **HTTP 直连后端**，
> 不引入 EMQX / 华为云 IoT 这类中间件。模拟器和真板子走同一套接口，
> **可以无缝替换，后端一行都不用改。**

---

## 一、总体路线（五个阶段）

| 阶段 | 做什么 | 需要硬件 | 产出 |
|---|---|---|---|
| ① 软件模拟 | 用 Python 模拟器喂数据 | 无 | 后端链路闭环（已完成，见 §二） |
| ② 板子点亮 | HM Nano 烧 OpenHarmony、跑通例程 | HM Nano + Type-C 线 | 板子能跑、串口有输出 |
| ③ 联网上报 | 板子连 WiFi，HTTP 上报后端 | 同上 | 真设备数据进后端 |
| ④ 接传感器 | 插 E53 板读真实温湿度/人体/烟雾 | + E53_IA1 / IS1 / SF1 | 数据来自物理世界 |
| ⑤ 带屏副设备 | IoT Std + 网口/WiFi 板做中控屏 | + Std + 扩展板 | 有线/无线接入的第二台设备 |

**不要跳阶段**：① 先跑通链路，后面每一步都有明确的"应该看到什么"，出问题好定位。

## 三、阶段②：BearPi-HM Nano 烧录上手指南

### 3.1 板子是什么

- 主控 **Hi3861**（RISC-V 32 位，160MHz，352KB SRAM / 2MB Flash）
- 跑 **OpenHarmony 轻量系统（LiteOS-M）** —— 这是真·鸿蒙设备端
- 板载 **WiFi**、**NFC**（碰一碰）、LED、2 个按键、CH340（Type-C 一线搞定供电+烧录+调试）

### 3.2 已确认的官方流程（2026-10-15 按官方文档核实）

> 官方文档就在源码里：`applications/BearPi/BearPi-HM_Nano/docs/quick-start/`
> （《BearPi-HM_Nano开发板如何烧录程序.md》《BearPi-HM_Nano十分钟上手-gitee方式.md》）

用户现有环境 = 官方 VMware Ubuntu 镜像 + MobaXterm(SSH) + RaiDrive(把虚拟机目录映射成 Windows 的 Z: 盘)。完整流程：

1. **编译（在虚拟机里，MobaXterm SSH 进去）**：
   ```bash
   cd /home/bearpi/project/bearpi-hm_nano
   python build.py BearPi-HM_Nano     # 看到 BUILD SUCCESS 即成功
   ```
   固件输出：`out/BearPi-HM_Nano/Hi3861_wifiiot_app_allinone.bin`
   （虚拟机镜像自带一份已编译好的，Z:\bearpi-hm_nano\out\BearPi-HM_Nano\ 下直接就有，第一次烧录可跳过编译）

2. **烧录（在 Windows 上，HiBurn 工具）**：
   - HiBurn 下载（官方百度云）：https://pan.baidu.com/s/1vSpPWvIhL8wCVGnEOjXS7g?pwd=1234 （提取码 1234）
   - ⚠️ **HiBurn.exe 会被 Windows Defender 误报为病毒**（Worm:Win32/AutoRun!atmn，无签名老工具的启发式误报，小熊派用户普遍遇到）。处理：先在「Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项」把 HiBurn 所在文件夹加白名单，再去「保护历史记录」还原被隔离的文件。顺序不能反，否则还原后立刻又被杀。
   - **关键前置：关闭 VMware 的 USB 捕获**（虚拟机 → 可移动设备 → CH340 → 断开连接；不行就挂起虚拟机再插拔 USB），否则 Windows 看不到串口
   - Type-C 连板子 → HiBurn 点 `Refresh` 选 COM 口 → `Setting → Com settings` 把 **Baud 改成 921600**
   - `Select file` 选 `Z:\bearpi-hm_nano\out\BearPi-HM_Nano\Hi3861_wifiiot_app_allinone.bin`
   - 勾选 `Auto burn` → 点 `Connect` → **按板子上的 RESET 键**开始下载
   - 出现 `Execution Successful` 即完成，**记得点 `Disconnect`**（不点的话串口日志工具打不开）

3. **看日志（MobaXterm Serial）**：同一个 COM 口，速率 **115200**（和烧录的 921600 不是一回事），按 RESET 看启动日志。

4. **改代码后的循环**：改 `applications/BearPi/BearPi-HM_Nano/sample/` 下的例程 → 虚拟机重新 `python build.py BearPi-HM_Nano` → Z 盘拿新 bin → HiBurn 烧录。

**路线对比**：上面这套就是官方推荐路径，无需 DevEco Device Tool；Windows 端只负责烧录和看日志，编译全在虚拟机里。

### 3.3 最容易翻车的六个点（血泪清单）

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | **串口驱动没装** | 设备管理器出现未知设备 / 找不到 COM 口 | 装 **CH340** 驱动 |
| 2 | **路径含中文或空格** | 编译报奇怪的错、找不到文件 | 源码和工具链放在**纯英文无空格**路径，越短越好 |
| 3 | **烧录时串口被占用** | 烧录失败 / 一直等待 | 关掉串口助手、DevEco 的 Monitor 后再烧 |
| 4 | **网线/WiFi 相关** | 板子烧好了但连不上 | 先只做"点亮 LED"，联网是阶段③的事，别混在一起调 |
| 5 | **端口被占用（本项目特有）** | 后端起不来 | 后端默认端口 **6893 被 WorkBuddy 占用**，启动加 `--server.port=8080` |
| 6 | **同时开两个后端实例** | 环境数值双倍跳 | 后端只能开一个实例（总方案踩坑 4） |

### 3.4 验收标准（阶段②结束）

- 串口能看到 OpenHarmony 启动日志；
- 官方例程（通常是 LED 闪烁 / Hello World）跑起来；
- **能自己改一行代码并烧进去看到变化** —— 这一步过了，阶段③才有意义。

## 四、阶段③：HM Nano 连 WiFi 并上报后端

### 4.1 上报的目标接口（和模拟器同一个）

```
POST http://<你电脑的局域网IP>:8080/api/room/{roomId}/environment/refresh
Header: token: <JWT>
Body:   {"temperature":25.1,"humidity":51,"smoke":6}
```

**四个必须对齐的点：**

1. **鉴权头名字是 `token`**，不是 `Authorization`（项目 `LoginInterceptor` 的约定）。
2. **token 从哪来**：设备端不方便做交互登录，实践做法是——
   - 先在 PC 上用 curl/Postman 调 `POST /api/user/login` 拿一个长期 token，**写死在设备配置里**；
   - 或者后端给设备加一个"设备专用上报接口"（见 §4.3）。
3. **IP 用局域网地址**（`ipconfig` 看到的有线 `172.16.103.x` 那个），不能用 `127.0.0.1`。
4. **Body 字段名严格对齐 `RoomEnvDTO`**：`temperature/humidity/aqi/co2/smoke/gas/hasGas`。传了哪个就覆盖哪个，没传的后端会自己抖一下。

### 4.2 固件里怎么写（概念骨架）

Hi3861 的 OpenHarmony 支持标准 BSD socket（底层 lwIP），所以最稳的做法是**自己用 socket 拼一个最小 HTTP POST**：

```
① 连 WiFi（STA 模式，用官方 wifi_device 接口填 SSID/密码，等拿到 IP）
② socket() → connect(PC的IP, 8080)
③ send() 拼接好的 HTTP 请求报文：
      POST /api/room/1/environment/refresh HTTP/1.1\r\n
      Host: 172.16.103.190:8080\r\n
      token: xxx\r\n
      Content-Type: application/json\r\n
      Content-Length: <len>\r\n
      \r\n
      {"temperature":25.1,"humidity":51}
④ recv() 读响应，判断里有没有 "code":200
⑤ 每 30 秒重复一次
```

> `wifi_device` 等具体接口名以小熊派官方 Codelab 的联网样例为准；
> HTTP 部分用 socket 自己拼最不依赖具体封装，也最容易排错。

### 4.3 更规范的做法（可选，建议组长拍板）

给后端加一个**不需要用户 token 的设备上报接口**，例如：

```
POST /api/device/report
Body: {"deviceKey":"HM-NANO-001","roomId":1,"temperature":25.1,"humidity":51}
```

优点：设备不用模拟用户登录、token 过期不影响设备、能按 deviceKey 定位是哪台设备。
代价：要给这个接口做**接入白名单/签名**，别裸奔（否则任何人都能改你家温湿度）。

**课程作业阶段**用 §4.1 的现成接口 + 写死 token 就够了，别过度设计。

### 4.4 验收标准（阶段③结束）

- 拔掉 PC 上的模拟器，App 里数据**依然在变**；
- 后端日志里 `[环境监测] 查询环境｜房间#1-客厅 …` 的数值来自板子；
- 把板子断电，数据停更 —— 证明数据源真的是它。

## 五、阶段④：接 E53 扩展板读真实传感器

E53 板插在主板的 E53 接口上，**上电前插好**。

| E53 板 | 读什么 | 对应后端字段 | 场景 |
|---|---|---|---|
| **E53_IA1** | 温湿度（SHT30/AHT20 类）+ 光照（BH1750 类）+ 风扇 + 灯 | `temperature` / `humidity` / `aqi`（光照可映射） | 环境监测 |
| **E53_IS1** | 人体红外（PIR）+ 蜂鸣器 | 无直接字段 → **触发控制指令**（开灯/本地蜂鸣） | 安防、回家亮灯 |
| **E53_SF1** | 烟雾 / 可燃气体（MQ-2 类）+ 蜂鸣器 | `smoke` / `gas` | 火灾/燃气报警 |
| **E53_SC1** | 光照 + LED 灯 | 作为被控灯（`light`） | 灯控 |

**关键提醒：**

- **人体感应没有后端字段**。这不是缺陷 —— 正确的建模是"**感应是触发条件，不是状态值**"：
  检测到有人 → 设备直接调 `POST /api/device/{灯id}/control {"power":"on"}`。
  这也正是模拟器里 `maybe_inject_events()` 干的事。
- **传感器读值要滤波**。裸读数会抖（比如温度 ±0.5℃ 跳），建议连续采 5 次取平均或滑动平均再上报，否则 App 里的曲线像心电图。
- **I2C 地址冲突**：多块 E53 板同时插时留意 I2C 从机地址，具体看各板原理图。

## 六、阶段⑤：IoT Std 当"带屏副设备"（可选）

- Std（STM32L431 + LiteOS）跑不了 OpenHarmony，但**当第二台设备**没问题：
  - 自带 **1.3" TFT 屏** → 可以做成"墙上中控面板"，显示各房间温湿度；
  - 用**自带的 WiFi 扩展板**或**周立功以太网模块**联网，上报同一套接口；
  - 也可以直接在上面调 `GET /api/home/overview` 把家庭总览画到屏上。
- 答辩价值：现场展示"**两台设备、三种接入方式（WiFi / 有线 / 4G）**"，
  比单台设备有说服力。但**这是加分项，不是必做项**，主线跑通再说。

## 七、排错速查

| 现象 | 先查什么 |
|---|---|
| 设备上报后 App 没变化 | ① body 字段名拼错？② token 过期？③ roomId 不是这个用户的房间？ |
| 返回 401 | 请求头名字必须是 `token`；值不带 `Bearer ` 前缀 |
| 返回 400「房间不存在」 | roomId 属于别的用户，`checkRoomOwner` 会拒 |
| 连接被拒 | 设备连的是 `127.0.0.1` 而不是 PC 的局域网 IP；或防火墙拦了 8080 |
| 数据每 30s 抖两次 | 后端 `SensorSimTask` 也在跑；模拟器/设备的值会覆盖它，无害 |
| 板子连不上 WiFi | 校园网通常要认证（Web 门户），HM Nano 连不上 —— **改用手机热点**最省事 |

> ⚠️ **校园网受限提醒**：学校网络多半需要网页认证或做了设备隔离，
> 开发阶段让板和 PC 都连**手机热点**，能省掉一大堆网络问题。
