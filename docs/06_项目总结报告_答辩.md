## 二、功能清单（截至 2026-09-29）

### 2.1 账号与安全
- 账号密码登录 / 注册（BCrypt 加盐哈希，库中无明文）
- 邮箱验证码注册（QQ SMTP 发信，Redis 60 秒冷却 + 验证码一次性）
- JWT 鉴权：拦截器统一校验请求头 `token`，默认全拦 + 白名单放行
- 广告启动页：15 秒倒计时 / 右上角跳过 / 跳转后销毁不可返回

### 2.2 设备控制（本项目核心）
- **17 种设备类型**，每种都有符合自身语义的可调功能：

| 类型 | 可调 | 只读（后端维护） |
|---|---|---|
| 灯 light | 开关 / 亮度 / 色温（暖·自然·冷白） | — |
| 空调 ac | 模式（冷·热·除湿·送风·自动）/ 温度 16~30 / 风速 / 扫风 | — |
| 插座 socket | 开关 | 实时功率 / 累计用电（后端计量） |
| 窗帘 curtain | 开合度 0~100 + 快捷档 | — |
| 浇花水泵 pump | 立即浇水 / 定时浇水 | 水量按分钟消耗 |
| 智能门禁 lock | 上锁 / 开锁 / 常开模式 | 电量 / 最近开关门 |
| 油烟机 hood | 风量档 0~3 / 照明 | — |
| 烟雾传感器 smoke_sensor | 监控开关 | 浓度（同步房间环境）/ 电量 |
| 冰箱 fridge | 冷藏温度 2~8℃ | — |
| 洗衣机 washer | 洗涤模式 / 开始停止 | 剩余分钟（每分钟倒计时） |
| 净水器 purifier | 开关 | 滤芯寿命 |
| 热水器 heater | 出水温度 35~65℃ | — |
| 烘干机 dryer | 烘干模式 / 开始停止 | 剩余分钟 |
| 扫地机器人 robot | 清扫模式 / 开始停止 | 电量（耗电 / 回充模拟） |
| 智能马桶 toilet | 座温档 / 除臭 / 夜灯 / 离座自动冲水 | — |
| 电视 tv | 音量 / 信号源 5 种 | — |
| 投影器 projector | 投影模式（影院·标准·省电）/ 音量 | — |

- **每日定时开关**：全部 17 种类型通用（`timerOn` / `timerOff`），后端每分钟扫描到点执行
- **控制指令唯一入口 `sanitizeAction()`**：只读字段丢弃 + 数值越界报错 + 枚举白名单，
  "前端能改什么、能改成什么值"由后端说了算，接口直调也伪造不了水量 / 电量

### 2.3 环境监测与联动
- 房间级环境数据：温度 / 湿度 / AQI / CO₂ / 烟雾（+ 厨房燃气），后端 30 秒模拟漂移
- 阈值判定只在后端（烟雾 50 / 燃气 200 / CO₂ 1500 / AQI 150），前端只展示
- 场景执行 + 定时场景（23:00 晚安模式等）

### 2.4 天气与商城
- 和风天气接入：**后端代理（KEY 不进 App）+ 10 分钟缓存**，33 城，60 分钟自动刷新
- 商城：商品 / 购物车 / 订单（下单事务：扣库存 + 明细快照 + 清购物车），金额一律 BigDecimal

### 2.5 UI
- 按米家风格整体美化：浅灰底 + 白色大圆角卡片 + 品牌绿强调 + 首页天空蓝渐变天气卡
- 17 种设备详情页各有专属面板（胶囊选项 / 滑杆 / 开关），功能不变、只动观感

## 四、技术亮点（答辩重点讲这四条）

### 4.1 语义字段驱动的设备状态（核心设计）

所有设备开关**不是**简单发 `{power: on/off}`，而是发各自类型的**语义字段**，
由后端反推 power 并联动：

```
窗帘  openPercent=0   → power=off     （开合度为 0 就是关）
水泵  watering=1      → power=on      （浇水中就是开）
门禁  locked=1        → power=off     （反向！上锁=关）
油烟机 gear=0         → power=off     （0 档=关）
洗衣机 running=1      → power=on，并补 remaining 倒计时
```

**为什么**：如果 power 和语义字段各存各的，迟早出现"开关显示开、窗帘开合度却是 0"的矛盾数据
（我们真的踩过，后用数据修复脚本扳正历史数据）。联动收敛在后端一处，前端永远不用猜。

### 4.2 后端说了算的指令清洗（sanitizeAction）

`control()` 的第一行永远是清洗：只读字段（水量 / 电量 / 电表读数）直接丢弃并告警；
数值字段越界抛业务异常；枚举字段（空调模式 / 信号源 / 各家电 mode）走白名单。
清洗后没有任何可执行项 → 400。

**为什么**：App 可以被反编译、接口可以被 Postman 直调。前端校验只管体验，
**安全边界必须划在后端**。加了新字段只需要改一处白名单。

### 4.3 通用定时 + 字典化的类型系统

- 定时开关做成**全类型通用**：后端 `applyTimer()` 把"开 / 关"映射到各类型的语义字段，
  加新类型只补一行；`DeviceTimedTask` 每分钟扫描全表比对 `HH:mm`，关机优先。
- 17 种类型收敛到后端 `DeviceTypes` 字典类（类型常量 / 中文名 / 默认状态 / mode 白名单），
  `types()` 接口、`add()` 默认状态全部从字典取。**加一种设备 = 字典加两行**，
  不再是散在 17 个 if-else 里漏一处就炸。

### 4.4 防乱码与可复现的演示态

- 导入铁律 `--default-character-set=utf8mb4`（真实踩坑：整库中文变 `?` 且不可逆）
- SQL 收敛为唯一自包含脚本 `init_all.sql`（建库 + 建表 + 全套演示数据，可单独交付、可反复执行），
  配套 `db_tool.py backup|reset|verify`（subprocess + utf-8 字节流绕开 PowerShell 编码坑，
  verify 自带中文 HEX 校验，杜绝 `3F` 问号）

## 五、踩坑与解决（挑答辩老师爱问的）

| # | 坑 | 根因 | 解决 |
|---|---|---|---|
| 1 | 前端编译失败：`NumberOption[]` 传给 `DeviceOption[]` | ArkTS 不做隐式类型兼容；同类选项数组有两种（字符串值 / 数值值） | 选项数组统一声明，转换函数收口；报错行号 ≠ 根因位置 |
| 2 | `@Builder` 里的 UI 不刷新 | `@Builder` 按值传参是**快照** | 选项行只传"数组 + 类别名"，选中判断 / 下发都用方法现算 |
| 3 | 首屏不是广告页 | 首屏由 `EntryAbility.loadContent()` 决定，`main_pages.json` 顺序不生效 | Index.aboutToAppear 里 `replaceUrl` 跳广告页；防死循环标志用 static 字段 |
| 4 | token 过期还能用 | Hutool `verify()` 只验签名不验有效期 | 必须用 `validate(0)` |
| 5 | 拦截器 401 前端收不到 JSON | 拦截器在 Controller 之前，异常不走全局处理器 | 拦截器里手写响应体 |
| 6 | 401 弹窗刷屏 | 轮询接口每分钟触发一次未登录 401 | 同文案 10 秒节流；未登录的 401 静默 |
| 7 | 水泵水量可被前端任意设置 | `status.putAll(action)` 前端发什么写什么 | 只读字段清洗 + 水量改为"开浇水位 − 已浇分钟"后端推算 |
| 8 | 整库中文变 `?` | 客户端非 utf8mb4 导入 | 导入命令写进脚本注释 + verify 的 HEX 校验 |
| 9 | 8080 端口"没进程却绑定失败" | Hyper-V/winnat 动态保留端口区间 | `netsh int ipv4 add excludedportrange` 永久保留 |
