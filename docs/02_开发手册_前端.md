## 第一章 怎么用这份手册

**建议阅读顺序**（别跳步，第 1、2 步是踩坑后加的）：

1. **先读第五章 5.0 节「ArkTS 严格模式避坑」**。ArkTS 比 TypeScript 严格得多，
   TS / Vue / 小程序里能跑的写法在这里会直接编译失败。先看这 5 类错误的正反例，能省掉 90% 的返工。
2. **再读第七章「常见问题排查」**，尤其是编译流程那几张表（改完先编译、Clean Project、串行改文件）。
3. 然后看第四章的**基础设施**（HttpClient、TokenStore、Const、api 层），这是全组必须统一的部分，谁都不许另起炉灶。
4. 页面开发照第六章抄：每个页面的代码结构都是「状态 → 生命周期 → 请求方法 → build UI」四段式。
5. 后端对应的接口实现见《02_开发手册_后端.md》。
6. 所有模拟数据统一用后端脚本导入（见后端手册的 `Mysql/init_all.sql`），**不要各自造数据**——
   测试时在 App 里加的「自测xx」房间/设备，答辩前请重跑脚本清掉。

> **动手前的三条纪律**（真的有人在这里栽过）：
> ① 一次只改一个 `.ets` 文件，改完核对落盘再改下一个；
> ② 改完先编译（`assembleHap`）再提交，别等合并到 `main` 才发现编译不过；
> ③ 报错"改了但没消失"时不要怀疑自己，先 `Build → Clean Project` 清缓存。

### 4.2 TokenStore.ets —— 登录态（内存 + 本地持久化双写）

> 📄 **文件**：`smarthome_app/entry/src/main/ets/common/TokenStore.ets` ｜ **负责人**：C（前端框架）

```typescript
// smarthome_app/entry/src/main/ets/common/TokenStore.ets
import { preferences } from '@kit.ArkData'

const STORE_NAME: string = 'smarthome_user'
const KEY_TOKEN: string = 'token'
const KEY_NICKNAME: string = 'nickname'

/**
 * 登录态管理。
 * 设计要点：token 同时存在内存和 Preferences 中——
 * 内存供 HttpClient 同步读取（避免每次请求都异步读磁盘），
 * Preferences 用于 App 重启后恢复登录态。
 */
export class TokenStore {
  private static token: string = ''
  private static nickname: string = ''

  /** App 启动时调用一次，从本地恢复登录态 */
  static async init(): Promise<void> {
    // 若编辑器提示 getContext 已废弃，可改为在页面里传 this.getUIContext().getHostContext()
    const pref = await preferences.getPreferences(getContext(), STORE_NAME)
    TokenStore.token = await pref.get(KEY_TOKEN, '') as string
    TokenStore.nickname = await pref.get(KEY_NICKNAME, '') as string
  }

  /** 同步读取 token，供 HttpClient 使用 */
  static getToken(): string {
    return TokenStore.token
  }

  static getNickname(): string {
    return TokenStore.nickname
  }

  /** 是否已登录：UI 判断登录态统一用这个方法 */
  static isLogin(): boolean {
    return TokenStore.token.length > 0
  }

  /** 登录成功后保存 */
  static async save(token: string, nickname: string): Promise<void> {
    TokenStore.token = token
    TokenStore.nickname = nickname
    const pref = await preferences.getPreferences(getContext(), STORE_NAME)
    await pref.put(KEY_TOKEN, token)
    await pref.put(KEY_NICKNAME, nickname)
    await pref.flush()          // 必须 flush，否则可能没真正落盘
  }

  /** 退出登录：清内存 + 清本地 */
  static async clear(): Promise<void> {
    TokenStore.token = ''
    TokenStore.nickname = ''
    const pref = await preferences.getPreferences(getContext(), STORE_NAME)
    await pref.delete(KEY_TOKEN)
    await pref.delete(KEY_NICKNAME)
    await pref.flush()
  }
}
```

### 4.3 HttpClient.ets —— 统一网络层（最重要）

> 📄 **文件**：`smarthome_app/entry/src/main/ets/common/HttpClient.ets` ｜ **负责人**：C（前端框架）

```typescript
// smarthome_app/entry/src/main/ets/common/HttpClient.ets
import { http } from '@kit.NetworkKit'
import { promptAction } from '@kit.ArkUI'
import { Env } from './Env'
import { TokenStore } from './TokenStore'

/** 与后端 Result 对应的统一响应结构 */
export interface ApiResponse<T> {
  code: number
  msg: string
  data?: T
}

/**
 * 统一网络请求类。页面必须通过 api/ 层调用它，禁止在页面里直接用。
 * 它负责四件事：拼 baseURL、带 token、解析 Result、统一错误提示。
 */
export class HttpClient {

  /**
   * 【踩坑记录 · 别改回去】基础设施类提示必须节流，否则会变成"弹幕"。
   *
   * 首页有 5 秒轮询。token 一旦失效，每个轮询周期都会拿到 401。
   * 早期版本在 401 分支里无条件 showToast + TokenStore.clear()，结果是：
   *   **每 5 秒弹一次"登录已过期"，同时每 5 秒写一次 Preferences**
   *   （clear() 内部是 delete + flush，是真实的磁盘 I/O），
   *   既烦人又白白拖慢界面。
   *
   * 现在两条规则：
   *   1) 只有"本地本来带着 token"才算登录过期。未登录时打开首页/智能页
   *      拿到的 401 是**预期行为**，不提示、也不清登录态（清了也没意义）。
   *   2) 真过期时，同一条提示 10 秒内只弹一次。
   */
  private static readonly TOAST_GAP_MS: number = 10000
  /** key = 提示文案，value = 上次弹出时间戳 */
  private static toastAt: Map<string, number> = new Map<string, number>()

  /** 登录态失效回调：由 Index 注册，用于让界面同步切回"未登录"形态 */
  private static authFailListener: (() => void) | null = null

  /** 注册登录态失效回调（App 启动时调用一次即可） */
  static setAuthFailListener(fn: () => void): void {
    HttpClient.authFailListener = fn
  }

  /** 带节流的提示：同一条文案 10 秒内只弹一次（用于 401 / 网络异常 / 服务异常） */
  private static notify(message: string): void {
    const now: number = Date.now()
    const last: number = HttpClient.toastAt.get(message) ?? 0
    if (now - last < HttpClient.TOAST_GAP_MS) return
    HttpClient.toastAt.set(message, now)
    promptAction.showToast({ message: message })
  }

  /**
   * 处理 401：清登录态 → 通知界面 → （节流后）提示一次。
   *
   * 注意顺序：必须在 clear() **之前** 判断"本来有没有 token"，
   * 因为 TokenStore.clear() 会先同步把内存里的 token 置空。
   */
  private static async handleUnauthorized(): Promise<void> {
    const hadToken: boolean = TokenStore.isLogin()

    // 规则 1：未登录时的 401 属于正常现象，静默返回
    //（同时这也天然防住了"清一次 → 没 token → 不再重复清"的重复磁盘写入）
    if (!hadToken) return

    await TokenStore.clear()
    // 通知界面：登录态已失效，相关页面要切回未登录形态并停止轮询
    if (HttpClient.authFailListener !== null) {
      HttpClient.authFailListener()
    }
    // 规则 2：节流提示
    HttpClient.notify('登录已过期，请重新登录')
  }

  private static async request<T>(method: http.RequestMethod, path: string,
                                  body?: object): Promise<ApiResponse<T>> {
    const client = http.createHttp()
    try {
      // 1. 组装请求头：有 token 就带上（后端拦截器靠它识别用户）
      const header: Record<string, string> = { 'Content-Type': 'application/json' }
      const token: string = TokenStore.getToken()
      if (token.length > 0) {
        header['token'] = token
      }

      // 2. 组装请求参数
      const options: http.HttpRequestOptions = {
        method: method,
        header: header,
        extraData: body === undefined ? undefined : JSON.stringify(body),
        connectTimeout: 8000,      // 连接超时 8 秒
        readTimeout: 8000
      }

      // 3. 发请求
      const resp: http.HttpResponse = await client.request(Env.BASE_URL + path, options)

      if (resp.responseCode !== 200) {
        // 走节流：轮询场景下服务端挂掉时不会刷屏
        HttpClient.notify(`服务异常（${resp.responseCode}）`)
        return { code: -1, msg: '服务异常' }
      }

      // 4. 解析 JSON
      const result: ApiResponse<T> = JSON.parse(resp.result as string)

      // 5. 统一处理特殊状态
      if (result.code === 401) {
        await HttpClient.handleUnauthorized()      // 清登录态 + 通知界面 + 节流提示
      } else if (result.code !== 200) {
        // 400 等业务错误：这是用户主动操作触发的，必须每次都提示，所以**不节流**
        promptAction.showToast({ message: result.msg })
      }
      return result
    } catch (err) {
      // 网络异常：多半是 IP 写错、后端没启动、手机与电脑不在同一网络。
      // 同样是轮询会反复触发的情况，要节流。
      HttpClient.notify('网络异常，请检查后端服务与 IP 配置')
      return { code: -1, msg: '网络异常' }
    } finally {
      client.destroy()      // 必须销毁，否则连接会泄漏
    }
  }

  static get<T>(path: string): Promise<ApiResponse<T>> {
    return HttpClient.request<T>(http.RequestMethod.GET, path)
  }

  static post<T>(path: string, body?: object): Promise<ApiResponse<T>> {
    return HttpClient.request<T>(http.RequestMethod.POST, path, body)
  }

  static put<T>(path: string, body?: object): Promise<ApiResponse<T>> {
    return HttpClient.request<T>(http.RequestMethod.PUT, path, body)
  }

  static delete<T>(path: string): Promise<ApiResponse<T>> {
    return HttpClient.request<T>(http.RequestMethod.DELETE, path)
  }
}
```

### 4.3.1 【必读】轮询与 401 的三条纪律

上面那段代码之所以比"能跑就行"的版本啰嗦，是因为被真实问题咬过。三条纪律：

| # | 纪律 | 不遵守的后果 |
|---|------|------------|
| 1 | **401 只有在"本地本来带着 token"时才算登录过期** | 未登录时打开首页/智能页，后端返回 401 是**正常**的；当成过期处理，用户一进 App 就被"登录已过期"糊脸 |
| 2 | **基础设施类提示（401 / 网络异常 / 服务异常）必须节流** | 首页 5 秒轮询一次，token 失效后提示每 5 秒弹一次，变成弹幕 |
| 3 | **未登录时不要发需要登录的请求，也不要起轮询** | 每个轮询周期都是白跑 + 401 + 写一次本地存储，纯浪费电和流量 |

> **一句话总原则**：**"后台自动触发"的提示要克制，"用户主动操作"的提示要明确。**
> 400 业务错误（如"库存不足""用户名已存在"）是用户点了按钮才出现的，所以**不节流**；
> 401 / 网络异常会在后台反复出现，所以**必须节流**。

> 另外注意 `TokenStore.clear()` 是**异步**的，但它会先同步把内存里的 token 置空。
> 所以"判断本来有没有 token"这一句必须写在 `await TokenStore.clear()` **之前**，
> 写在后面就永远是"没有 token"，过期提示永远不会弹。

### 4.3.2 操作提示：什么该弹、什么不该弹

产品要求「任何操作下方都有小字反馈」。落地时按两条原则执行，避免两种极端
（要么点了没反应像卡死，要么每个滑杆刻度都弹一条像弹幕）：

| 操作类型 | 是否 toast | 例子 |
|---------|-----------|------|
| **改数据且留在本页** | ✅ 成功后必须弹 | 开关设备、改数量、删房间、启停自动化 |
| **改数据后跳到结果页** | ❌ 不弹（结果页就是反馈） | 提交订单 → 支付结果页 |
| **滑杆拖动** | ✅ 只在**松手（End）/点击（Click）**弹一次 | 温度、亮度、窗帘开合 |
| 纯浏览（切房间、切 Tab、跳详情） | ❌ 不弹 | 页面变化本身就是反馈 |

```typescript
// 滑杆标准写法：拖动过程静默，定值时刻才提示
this.doControl({ temperature: Math.round(value) })
if (mode === SliderChangeMode.End || mode === SliderChangeMode.Click) {
  promptAction.showToast({ message: `已把「${this.device!.name}」温度调到 ${Math.round(value)}℃` })
}
```

> toast 本身是**覆盖式**的：连点 "+" 不会堆成弹幕，后一条直接顶掉前一条。
> 所以「用户主动操作」的提示**不需要节流**（与 4.3.1 的基础设施提示相反）。
>
> 本项目已覆盖的操作：设备卡片开关、详情页开关与三根滑杆、场景执行/启停、
> 房间增改、购物车数量/移除、地址增删、添加设备、退出登录。
> 后端对应每笔操作还有一份服务端记录（`operation_log` 表，见后端手册 2.6）。

### 4.5 Format.ets —— 格式化工具

> 📄 **文件**：`smarthome_app/entry/src/main/ets/common/Format.ets` ｜ **负责人**：C（前端框架）

```typescript
// smarthome_app/entry/src/main/ets/common/Format.ets
import { DeviceStatus, RoomEnv } from '../model/Device'    // import 习惯放文件顶部

export class Format {
  /** 金额：19 → ¥19.00 */
  static money(amount: number): string {
    return `¥${amount.toFixed(2)}`
  }

  /** 设备状态一句话描述：设备卡片副标题用 */
  static deviceStatusText(type: string, status: DeviceStatus): string {
    const on: boolean = status.power === 'on'
    if (type === 'light') {
      return on ? `已开启 · 亮度 ${status.brightness ?? 0}%` : '已关闭'
    }
    if (type === 'ac') {
      return on ? `运行中 · ${status.temperature ?? 26}℃` : '已关闭'
    }
    if (type === 'curtain') {
      // 窗帘口径：开合度即开关，0% 显示"已关闭"
      const percent: number = status.openPercent ?? 0
      return percent <= 0 ? '已关闭' : `开启 ${percent}%`
    }
    if (type === 'pump') {
      // 水泵口径：只看 watering，不看 power（后端会把两者联动一致）
      if (status.watering === 1) return `浇水中 · ${status.duration ?? 10}分钟后停`
      const plan: string = status.waterPlan ?? ''
      return plan.length > 0 ? `待机 · 定时 ${plan}` : `待机 · 水量 ${status.waterLevel ?? 0}%`
    }
    if (type === 'lock') {
      // 门禁口径：locked=1 已上锁、0 已开锁（与 power 反向）
      const locked: boolean = (status.locked ?? 1) === 1
      return locked ? `已上锁 · 电量 ${status.battery ?? 0}%` : `已开锁 · 电量 ${status.battery ?? 0}%`
    }
    return on ? '已开启' : '已关闭'
  }

  /**
   * 环境告警一句话描述：主页环境面板的红色告警条用
   * 把"哪几项越界了"拼成一行，没有告警时返回空串
   */
  static envAlarmText(env: RoomEnv): string {
    const parts: string[] = []
    if (env.smokeAlarm === 1) parts.push(`烟雾报警 ${env.smoke}ppm`)
    if (env.gasAlarm === 1) parts.push(`燃气泄漏 ${env.gas}ppm`)
    if (env.co2Level.indexOf('偏高') >= 0) parts.push(`CO₂ ${env.co2}ppm`)
    if (env.airLevel.indexOf('污染') >= 0) parts.push(`空气质量 ${env.aqi}`)
    return parts.join('｜')
  }
}
```

> **注意**：`deviceStatusText` 里已经**没有** `temp_sensor` 分支了。温湿度不再是"某台设备的状态"，而是房间的环境属性，走 `RoomEnv` + `Format.envAlarmText`（见 6.19 节）。
>
> **2026-09 新增**：`pump`（水泵）与 `lock`（门禁）两个分支。三条"语义字段驱动 power"的口径
> 一定要记住——前端**只发语义字段，不发 `power`**：
>
> | 类型 | 前端发的字段 | 后端联动 | 卡片开关的判据 |
> |------|-------------|---------|---------------|
> | `curtain` | `openPercent` 0-100 | 0→off，>0→on | `openPercent > 0` |
> | `pump` | `watering` 0/1（可带 `duration`） | 1→on，0→off | `watering === 1` |
> | `lock` | `locked` 0/1 | **反向**：1→off，0→on | `locked === 0` |
>
> 这样卡片开关、详情页专属按钮、滑杆三者永远不会互相矛盾。

## 第五章 数据模型与 api 层

### 5.0 【必读】ArkTS 严格模式：5 类编译错误与正确写法

ArkTS 比 TypeScript 严格得多。下面 5 类写法在 TS / Vue / 小程序里都没问题，在这里会**直接编译失败**
（控制台末尾出现 `COMPILE RESULT:FAIL`）。动手前先过一遍，能省掉 90% 的报错。

> 🔴 **报错率最高的一种，其实不在下面 5 类里：`Cannot find name 'promptAction'`。**
> ArkTS 不做全局注入 —— `promptAction.showToast(...)`、`router.pushUrl(...)` 用到谁，
> 就必须从 `@kit.ArkUI` 显式 import 谁，少一个就编译不过：
>
> ```typescript
> import { router, promptAction } from '@kit.ArkUI'   // 两个都要，别只写 router
> ```
>
> 本手册的页面模板为了行宽，**部分代码块只写了 `import { router }`**，
> 而那些页面里其实用了 `promptAction` —— 照抄时请自己补齐这一行。

#### ① 裸对象字面量不能传给 `object` 参数（arkts-no-untyped-obj-literals）

```typescript
// ❌ 错误：直接把字面量塞进接口参数
return HttpClient.post<void>('/api/room', { name: name })

// ✅ 正确：先声明接口，再赋给一个变量
export interface RoomParam {
  id?: number
  name: string
}
const body: RoomParam = { name: name }
return HttpClient.post<void>('/api/room', body)
```

**规则：所有请求体都要在 api 文件里声明成 interface**（见 5.6）；设备控制指令统一用
`model/Device.ets` 里的 `DeviceAction`。

#### ② ForEach 的两个回调参数都必须标类型（arkts-no-any-unknown）

```typescript
// ❌ 错误：item 隐式推断成 any
ForEach(order.items, (item) => { ... })

// ✅ 正确：两个回调都标类型，并补上 key 生成器
ForEach(order.items, (item: OrderItem, index: number) => { ... },
        (item: OrderItem, index: number) => `${item.goodsId}_${index}`)
```

key 要用能唯一定位的值：`order.items` 里同一商品 id 可能重复，所以拼上 index。

> ⚠️ **【踩坑记录】key 里必须包含"会变的数据"，不能只用 id！**
>
> ArkUI 的 ForEach 在重新渲染时会对比前后两组 key：**key 相同 → 认为这条数据没变 →
> 直接复用旧组件，不会把新数据同步给它的 `@Prop`**。
>
> 真实案例：首页设备卡片的 key 写成 `device.id.toString()`，首页每 5 秒轮询一次，
> 后端环境数据也每 30 秒在变，但**卡片上的状态文字永远不动** ——
> 因为 id 没变、key 没变，组件根本没被更新。顶部"室内环境"主卡是普通
> `@State` 直接绑定 `Text`，所以会动 —— 同一个页面一半动一半不动，特别迷惑人。
>
> 真实案例 2：购物车 key 也只写了 `item.id`，点 "+" 改数量时**数字不动、
> 底部合计却实时变** —— 合计是页面 build 里直接算的（重渲染就更新），
> 而数量步进器是子组件，key 不变就复用旧的、`@Prop value` 不同步。
> 修复：key 改成 `` `${item.id}_${item.quantity}` ``。
>
> 真实案例 3：环境监测面板的指标格 key 只写了 `cell.key`（`'temperature'` 这种固定串），
> 导致**轮询一直有新数据、数字却冻在第一次的值**。修复：key 拼上数值与等级文案。
> **自查口诀：凡是"父页面会变、子组件冻住"的界面，先查 ForEach 的 key。**
>
> 正确写法：把会变的字段拼进 key，数据一变 key 就变，组件才会用新数据重建：
>
> ```typescript
> // ✅ 设备卡片：状态一变 key 就变
> (device: Device) => `${device.id}_${device.name}_${device.online}_${JSON.stringify(device.status)}`
> // ✅ 场景：enabled 开关状态会变
> (scene: Scene) => `${scene.id}_${scene.enabled}_${scene.name}`
> // ✅ 订单：status 会变（取消订单后重拉列表，状态文字要跟着变）
> (order: Order) => `${order.id}_${order.status}`
> // ✅ 环境指标格：每个数值都会变
> (cell: EnvMetricCell) => `${cell.key}_${cell.value}_${cell.level}`
> ```
>
> **自查方法**：给列表加载数据后，手动改数据库里某条记录的一个展示字段，
> 界面不变就是 key 只用了 id。

> ⚠️ **【踩坑记录】@Builder 按值传参，同样会"冻住"！**
>
> `@Builder` 函数的参数是**按值传递**的：首次渲染时求值一次，之后页面状态再变，
> Builder 里的 UI **不会跟着刷新**——它拿到的只是当初那份拷贝。
>
> 真实案例：设备详情页的"模式选择 chip"（制冷/制热/除湿/送风）抽成 `@Builder
> modeChip(label, active)`，点"制热"后高亮**永远停在第一次选中的那个**——
> 传进去的 `active` 是值拷贝，状态变了 Builder 也不知道。
>
> **修复思路（二选一）**：
> ① 不要抽 Builder，把这段 UI 直接内联写在 `build()` 里，让条件表达式直接依赖
>    `@State`（推荐，Demo 里就是这么改的）；
> ② 必须抽的话，给 Builder 传**状态对象本身**（`this.xxx`）而不是算好的布尔值，
>    且用 `@Builder` + 按引用传递的写法（对象字面量参数），新手建议直接用 ①。
>
> **自查口诀（姊妹版）**：`@Builder` 里依赖了会变的状态却高亮/选中不动，
> 八成是按值传参把"变化"挡在了外面。

#### ③ 箭头函数不能隐式返回 Promise（arkts-no-implicit-return-types）

```typescript
// ❌ 错误：右侧是 async 函数（返回 Promise），但组件属性声明是 () => void
onChanged: () => this.loadOverview(true)

// ✅ 正确：用花括号包住函数体，把返回值"吞掉"
onChanged: () => {
  this.loadOverview(true)
}
```

#### ④ 不许用 `any` / `unknown`，请声明 interface 后断言

```typescript
// ❌ const params: any = router.getParams()
// ✅
interface DetailParams { deviceId: number }
const params = router.getParams() as DetailParams
```

#### ⑤ 对象数组必须用具体类型，不能写 `object[]`

```typescript
// ❌ 错误
const orderItems: object[] = this.items.map((item: CartItem) => {
  return { goodsId: item.goodsId, quantity: item.quantity }
})

// ✅ 正确
const orderItems: OrderItemParam[] = this.items.map((item: CartItem) => {
  const orderItem: OrderItemParam = { goodsId: item.goodsId, quantity: item.quantity }
  return orderItem
})
```

#### ⑥ 编译报错怎么读

- 报错长这样：`ERROR: 10605038 ArkTS Compiler Error` + `Error Message: ...` + `At File: 路径:行:列`，
  按行号去找就行。
- **先改第一条 ERROR**：ArkTS 常因一个错级联出一串，改完第一条再重新编译，报错数往往直接归零。
- **WARN 不阻塞编译**：目前项目里有 129 条 WARN，全是 `router.pushUrl` / `showToast` / `getContext`
  已废弃之类的提示，能跑就不用管。
- **重编后报错"变了但没消失"**：多半是 hvigor 守护进程读了旧缓存，见下面 5.0.2。

#### ⑦ 【必读】改文件与编译的正确节奏

这一节讲的不是语法，是**流程**——25 个 ERROR 里有相当一部分是流程问题导致的，不是不会写。

**5.0.1 一次只改一个文件，改完核对落盘**

同时改多个 `.ets` 文件时，容易出现"明明改了、重新编译却没有"的情况：
后发起的改动基于旧快照，把先前的改动覆盖掉了。

正确节奏：

1. 改 **一个** 文件 → `Ctrl+S` 保存 → 确认编辑器标签页上的 `*` 号消失；
2. 用搜索或重新打开该文件，**肉眼核对关键字真的写进去了**；
3. 确认无误再改下一个文件；
4. 同一文件要多处修改时，**一处一处串行做**，不要并发。

**5.0.2 报错"改了但没消失"→ 清缓存**

hvigor 守护进程会缓存文件快照，导致报错行号对不上、已修好的错又冒出来。两种清法：

| 方式 | 操作 |
|------|------|
| DevEco Studio 内 | 菜单 `Build → Clean Project`，然后重新编译 |
| 命令行 | 编译命令末尾加 `--no-daemon`，强制不用常驻进程 |

### 6.1 Index.ets —— 底部 5 个 Tab 主框架

> 📄 **文件**：`smarthome_app/entry/src/main/ets/pages/Index.ets` ｜ **负责人**：C（前端框架）

```typescript
// smarthome_app/entry/src/main/ets/pages/Index.ets
import { TokenStore } from '../common/TokenStore'
import { HttpClient } from '../common/HttpClient'
import { Const } from '../common/Const'
import { HomePage } from './home/HomePage'
import { SmartPage } from './smart/SmartPage'
import { ProductPage } from './product/ProductPage'
import { ShopPage } from './shop/ShopPage'
import { MinePage } from './mine/MinePage'

interface TabItem {
  title: string
  icon: Resource
}

@Entry
@Component
struct Index {
  @State currentIndex: number = 0
  /**
   * 刷新信号：每 +1 表示「当前 Tab 该重新拉一次数据」。
   *
   * 【为什么必须有它】Tabs 内嵌的子页面是 @Component 而不是 @Entry，
   * 它们没有 onPageShow 生命周期，aboutToAppear 又只在整个 Tab 首次创建时跑一次。
   * 结果：从登录页 router.back() 回来时，MinePage 不会重新执行 refresh()，
   * 它的 @State isLogin 还停在登录前的 false —— 表现就是
   * **弹出"登录成功"提示、页面却依然显示未登录**，很容易被误判成"请求没发出去"。
   * 所以由 @Entry 的 Index 统一广播信号，子组件用 @Prop + @Watch 接收。
   */
  @State refreshTick: number = 0
  private tabs: TabItem[] = [
    { title: '主页', icon: $r('app.media.ic_tab_home') },
    { title: '智能', icon: $r('app.media.ic_tab_smart') },
    { title: '产品', icon: $r('app.media.ic_tab_product') },
    { title: '商城', icon: $r('app.media.ic_tab_shop') },
    { title: '我的', icon: $r('app.media.ic_tab_mine') }
  ]

  aboutToAppear() {
    // token 失效时由 HttpClient 回调到这里：广播一次刷新，
    // 让各个 Tab 切回"未登录"形态并停掉轮询（不然会一直 401 刷屏）
    HttpClient.setAuthFailListener(() => {
      this.refreshTick++
    })
    // 启动时恢复登录态（token 从本地读进内存）。
    // init 是异步的，必须等它读完再广播信号——否则子页面会在 token 还没加载出来时
    // 就判断成"未登录"，重启 App 后登录态看着就丢了。
    TokenStore.init().then(() => {
      this.refreshTick++
    })
  }

  /** 从登录页 / 详情页 router.back() 回到本页时触发 */
  onPageShow() {
    this.refreshTick++
  }

  /** 自定义 Tab 按钮：图标 + 文字，选中变橙色 */
  @Builder
  tabBuilder(index: number, item: TabItem) {
    Column({ space: 2 }) {
      Image(item.icon).width(22).height(22)
        .fillColor(this.currentIndex === index ? Const.BRAND : Const.TEXT_SUB)
      Text(item.title).fontSize(11)
        .fontColor(this.currentIndex === index ? Const.BRAND : Const.TEXT_SUB)
    }.justifyContent(FlexAlign.Center).height('100%').width('100%')
  }

  build() {
    // Tabs 组件 + barPosition.End 实现底部导航
    Tabs({ barPosition: BarPosition.End, index: this.currentIndex }) {
      // visible：只让"看得见"的那个 Tab 轮询，切走的页面停止轮询（省电省流量）
      TabContent() {
        HomePage({ refreshTick: this.refreshTick, visible: this.currentIndex === 0 })
      }.tabBar(this.tabBuilder(0, this.tabs[0]))

      TabContent() {
        SmartPage({ refreshTick: this.refreshTick })
      }.tabBar(this.tabBuilder(1, this.tabs[1]))

      TabContent() { ProductPage() }.tabBar(this.tabBuilder(2, this.tabs[2]))
      TabContent() { ShopPage() }.tabBar(this.tabBuilder(3, this.tabs[3]))

      // 我的页显示登录态，必须接收刷新信号（见上面 refreshTick 的注释）；
      // onLogout 用于"退出登录"后让首页/智能页也切回未登录形态
      TabContent() {
        MinePage({
          refreshTick: this.refreshTick,
          onLogout: () => {
            this.refreshTick++
          }
        })
      }.tabBar(this.tabBuilder(4, this.tabs[4]))
    }
    .barHeight(56)
    .backgroundColor(Const.PAGE_BG)
    .onChange((index: number) => {
      this.currentIndex = index
      this.refreshTick++      // 切 Tab 时也刷新一次，保证看到最新状态
    })
  }
}
```

> 注意：被 `TabContent` 内嵌的 5 个页面要写成 `@Component`（不是 `@Entry`），导出 struct 供上面引用。
>
> ⚠️ **Tab 子页面拿不到 `onPageShow`** —— 这是本项目最容易踩的一个架构坑：
>
> | 你可能以为 | 实际情况 |
> |-----------|---------|
> | 子页面有 `onPageShow`，返回时会自动刷新 | ❌ `onPageShow` 是 `@Entry` 页面专有，`@Component` 没有 |
> | `aboutToAppear` 每次切回来都会跑 | ❌ 只在组件**首次创建**时跑一次，之后一直复用 |
> | 登录成功后页面自然就变已登录了 | ❌ 状态没被重新读取，UI 停在旧值 |
>
> **统一解法**：`@Entry` 的 Index 广播 `refreshTick`，需要感知"页面重新可见"的子组件接一个
> `@Prop @Watch('回调名') refreshTick: number = 0`，在回调里重新拉数据。
> 目前 **MinePage（登录态）、HomePage（未登录时不能起轮询）、SmartPage（场景列表要登录）**
> 三个都接了这个信号；以后新增任何"显示登录态 / 显示会变的列表"的 Tab 页，都要按这个模式接上。
>
> 另外 HomePage 多接了一个 `visible`，用来在切走 Tab 后停止轮询 —— 详见 6.2 的注释。

### 6.2 主页 HomePage.ets —— 环境监测面板 + 设备卡片 + 轮询刷新

> 环境数据来自 `HomeOverview.environments`（与 `rooms` 等长同序），
> 不再单独读某台温湿度计设备。轮询 / 刷新约定不变。

> 📄 **文件**：`smarthome_app/entry/src/main/ets/pages/home/HomePage.ets` ｜ **负责人**：D（前端页面）

```typescript
// smarthome_app/entry/src/main/ets/pages/home/HomePage.ets
import { router } from '@kit.ArkUI'
import { DeviceApi } from '../../api/DeviceApi'
import { Device, Room, RoomEnv } from '../../model/Device'
import { Const } from '../../common/Const'
import { TokenStore } from '../../common/TokenStore'
import { DeviceCard } from '../../view/DeviceCard'
import { EnvironmentPanel } from '../../view/EnvironmentPanel'
import { EmptyView } from '../../view/EmptyView'

@Component
export struct HomePage {
  @State homeName: string = '我的家'
  @State rooms: Room[] = []
  @State currentRoomIndex: number = 0
  @State devices: Device[] = []
  @State environments: RoomEnv[] = []      // 环境监测数据，与 rooms 同序
  @State envRefreshing: boolean = false     // 环境手动刷新中（防连点）
  @State isLogin: boolean = false

  /**
   * 刷新信号（来自 Index）：登录成功 router.back() 回来时 +1。
   * Tab 子页面没有 onPageShow，靠它才知道"该重新拉数据了"。
   */
  @Prop @Watch('onSignalChange') refreshTick: number = 0

  /**
   * 当前 Tab 是否可见（来自 Index 的 currentIndex === 0）。
   *
   * 【为什么要它】Tabs 的子页面切走后**不会销毁**，setInterval 会一直跑。
   * 用户停在"商城"页时，首页还在后台每 5 秒发一次请求 —— 纯属浪费电和流量。
   * 让轮询跟着可见性起停，性能和体验都更合理。
   */
  @Prop @Watch('onSignalChange') visible: boolean = true

  private timerId: number = -1        // 轮询定时器 id，便于清理
  private loading: boolean = false    // 上一轮请求是否还在飞（防止请求堆积）

  /** 轮询间隔：既能看到控制结果，也能看到环境数据的变化 */
  private static readonly POLL_MS: number = 5000

  /** refreshTick / visible 任一变化都重新同步一次轮询状态 */
  onSignalChange() {
    this.sync()
  }

  aboutToAppear() {
    this.sync()
  }

  aboutToDisappear() {
    this.stopPolling()      // 不清会内存泄漏并在后台持续发请求
  }

  /**
   * 按「登录态 + 可见性」决定要不要拉数据、要不要轮询。
   * 未登录时**什么都不请求** —— 否则每个轮询周期都会拿到 401，
   * 既弹提示又白耗性能（早期版本就是这样被刷屏的）。
   */
  async sync() {
    this.isLogin = TokenStore.isLogin()
    if (!this.isLogin) {
      this.stopPolling()
      // 未登录就把数据清空，避免残留上一个账号的设备
      this.rooms = []
      this.devices = []
      this.environments = []
      return
    }
    if (!this.visible) {
      this.stopPolling()
      return
    }
    await this.loadOverview(true)      // 切回本 Tab 立即刷新一次
    this.startPolling()
  }

  startPolling() {
    if (this.timerId !== -1) return     // 已经在轮询，别重复起（否则请求会成倍增长）
    this.timerId = setInterval(() => {
      this.loadOverview(true)
    }, HomePage.POLL_MS)
  }

  stopPolling() {
    if (this.timerId !== -1) {
      clearInterval(this.timerId)
      this.timerId = -1
    }
  }

  /**
   * 加载首页总览
   * @param silent 静默刷新（轮询用）：不显示 loading，避免界面闪动
   */
  async loadOverview(silent: boolean = false) {
    // 防重入：上一轮还没返回就跳过这次，避免网络慢时请求越堆越多
    if (this.loading) return
    if (!TokenStore.isLogin()) {
      this.stopPolling()
      return
    }
    this.loading = true
    try {
      const res = await DeviceApi.overview()
      if (res.code === 200 && res.data) {
        this.homeName = res.data.homeName
        this.rooms = res.data.rooms
        this.devices = res.data.devices
        this.environments = res.data.environments
        // 房间数量变化时修正选中索引，防止越界
        if (this.currentRoomIndex >= this.rooms.length) this.currentRoomIndex = 0
      } else if (res.code === 401) {
        // token 失效：停止轮询，否则会一直 401（HttpClient 已负责清理和提示）
        this.stopPolling()
        this.isLogin = false
      }
    } finally {
      this.loading = false
    }
  }

  /** 按当前选中房间过滤设备 */
  currentDevices(): Device[] {
    if (this.rooms.length === 0) return this.devices
    const roomId: number = this.rooms[this.currentRoomIndex].id
    return this.devices.filter((d: Device) => d.roomId === roomId)
  }

  /**
   * 当前选中房间的环境数据。
   * environments 与 rooms 是**等长同序**的（后端按房间顺序拼），
   * 所以直接按下标取即可，不用再 find —— 少一次遍历，也不会错位。
   */
  currentEnv(): RoomEnv | null {
    if (this.environments.length === 0) return null
    if (this.currentRoomIndex >= this.environments.length) return null
    return this.environments[this.currentRoomIndex]
  }

  /**
   * 手动刷新当前房间的环境（用户主动点击 → 明确反馈，不节流）。
   * 不传参数 = 只触发一次采样（各项小幅波动）；拿到结果后直接覆盖当前房间的数据，
   * 界面立刻更新，不用等下一轮 5 秒轮询。
   */
  async refreshEnvironment() {
    const env = this.currentEnv()
    if (env === null) return
    this.envRefreshing = true
    try {
      const param: RoomEnvParam = {}      // 空对象 = 只采样不改值
      const res = await DeviceApi.refreshEnvironment(env.roomId, param)
      if (res.code === 200 && res.data) {
        // 用 slice() 造新数组再整体赋值：直接改 environments[i] 不会触发 @State 刷新
        const next: RoomEnv[] = this.environments.slice()
        next[this.currentRoomIndex] = res.data
        this.environments = next
        if (res.data.alarmCount > 0) {
          promptAction.showToast({ message: '采样完成，发现环境告警' })
        } else {
          promptAction.showToast({ message: '环境数据已刷新' })
        }
      }
    } finally {
      this.envRefreshing = false
    }
  }

  /** 主卡上的一句话摘要：温度 + 湿度 + 空气质量（没有环境数据时显示占位） */
  private envSummary(): string {
    const env = this.currentEnv()
    if (env === null) return '暂无环境数据'
    return `${env.temperature.toFixed(1)}℃  湿度 ${env.humidity}%  ${env.airLevel}`
  }

  build() {
    Column() {
      // ---------- 顶部标题栏 ----------
      Row() {
        Text(this.homeName).fontSize(20).fontWeight(FontWeight.Medium)
          .fontColor(Const.TEXT_MAIN)
        Blank()
        Text('+').fontSize(26).fontColor(Const.BRAND)
          .onClick(() => {
            // 未登录先引导登录（登录态差异处理）
            if (!TokenStore.isLogin()) {
              router.pushUrl({ url: 'pages/login/LoginPage' })
              return
            }
            router.pushUrl({ url: 'pages/device/AddDevicePage' })
          })
      }
      .width('100%').padding({ left: 16, right: 16, top: 12, bottom: 12 })

      Scroll() {
        Column({ space: Const.CARD_GAP }) {
          // ---------- 环境主卡（品牌蓝：整个页面的视觉锚点）----------
          Row() {
            Column({ space: 4 }) {
              Text('室内环境').fontSize(12).fontColor('rgba(255,255,255,0.75)')
              Text(this.envSummary())
                .fontSize(22).fontWeight(FontWeight.Medium).fontColor(Color.White)
            }.alignItems(HorizontalAlign.Start)
            Blank()
            // 有告警时右上角直接提示，不用点进面板才知道
            Text(this.currentEnv() !== null && this.currentEnv()!.alarmCount > 0
              ? '⚠ 有告警' : '环境正常')
              .fontSize(11).fontColor('rgba(255,255,255,0.75)')
          }
          .width('100%').padding(16)
          .backgroundColor(Const.BRAND).borderRadius(Const.CARD_RADIUS)

          // ---------- 环境监测面板（温度/湿度/空气质量/CO₂/烟雾，厨房多一项燃气）----------
          // 注意 onRefresh 要写成带花括号的形式：
          // 组件属性声明是 () => void，直接写 () => this.refreshEnvironment()
          // 会"隐式返回 Promise"，ArkTS 严格模式直接编译失败（见 5.0 ③）
          EnvironmentPanel({
            env: this.currentEnv(),
            refreshing: this.envRefreshing,
            onRefresh: () => {
              this.refreshEnvironment()
            }
          })

          // ---------- 房间切换 ----------
          Row({ space: 8 }) {
            ForEach(this.rooms, (room: Room, index: number) => {
              Text(room.name)
                .fontSize(13)
                .padding({ left: 14, right: 14, top: 7, bottom: 7 })
                .borderRadius(16)
                .backgroundColor(index === this.currentRoomIndex ? Const.BRAND : Const.CARD_BG)
                .fontColor(index === this.currentRoomIndex ? Color.White : Const.TEXT_MAIN)
                .onClick(() => {
                  this.currentRoomIndex = index
                  this.loadOverview(true)     // 切房间立即刷新
                })
            }, (room: Room) => `${room.id}_${room.name}`)
          }.width('100%')

          // ---------- 设备网格 ----------
          if (this.currentDevices().length === 0) {
            EmptyView({
              text: '这个房间还没有设备',
              buttonText: '添加设备',
              onAction: () => router.pushUrl({ url: 'pages/device/AddDevicePage' })
            })
          } else {
            Grid() {
              ForEach(this.currentDevices(), (device: Device) => {
                GridItem() {
                  DeviceCard({
                    device: device,
                    onChanged: () => this.loadOverview(true)   // 控制成功后刷新
                  })
                }
              }, (device: Device) => {
                // 【关键】key 不能只用 id！ArkUI 的 ForEach 在 key 相同时会认为
                // "这条数据没变"，直接复用旧组件、不把新数据同步进去 ——
                // 表现就是：轮询明明拿到了最新状态，设备卡片却永远不刷新。
                // 把会变的字段拼进 key，状态一变 key 就变，组件才会用新数据重建。
                return `${device.id}_${device.name}_${device.online}_${JSON.stringify(device.status)}`
              })
            }
            .columnsTemplate('1fr 1fr')
            .columnsGap(Const.CARD_GAP)
            .rowsGap(Const.CARD_GAP)
            .height(this.currentDevices().length <= 2 ? 120 : 240)
          }
        }
        .padding({ left: 16, right: 16, bottom: 16 })
      }
      .layoutWeight(1)               // 占满剩余空间，实现内容滚动
      .scrollBar(BarState.Off)
    }
    .width('100%').height('100%').backgroundColor(Const.PAGE_BG)
  }
```

### 6.3 view/DeviceCard.ets —— 设备卡片组件

> **样式说明（2026-09 视觉升级，B 磁贴式）**：卡片改为「左侧彩色圆角图标块 +
> 右侧设备名/状态文字 + 底部状态行」的磁贴布局，主色随米家蓝 `#3478F6`。
> 窗帘卡的"开关"由 `openPercent > 0` 推导（详见 5.0 ② 与接口文档第四节），
> 点开关发的是 `openPercent`（0 关 / 100 开）而不是 `power`。
> 下面代码为早期版本骨架，**布局细节以工程内最新 `DeviceCard.ets` 为准**，接口与刷新约定不变。

> **2026-09-23 修复（重要）**：本组件原来的 `togglePower()` 对**所有类型**都发 `{power: next}`。
> 灯 / 空调 / 插座没事，但**窗帘 / 水泵 / 门禁的 `power` 是后端由语义字段联动推导的**，
> 直接发 `power` 会绕过联动，把 `power` 与语义字段变成两个互相打架的事实 ——
> 点一下窗帘卡片的圆点，圆点变绿了，详情页却还显示"已全关"。
>
> 正确做法：**按类型发语义字段**，判断"开没开"也用各自的语义口径。
>
> ```typescript
> private isOn(): boolean {
>   const st: DeviceStatus = this.device.status
>   const t: string = this.device.type
>   if (t === Const.DEV_CURTAIN) return (st.openPercent ?? 0) > 0
>   if (t === Const.DEV_PUMP)    return st.watering === 1
>   if (t === Const.DEV_LOCK)    return (st.locked ?? 1) === 0     // 门禁反向：0 才是"开"
>   return st.power === 'on'
> }
>
> async togglePower() {
>   const t: string = this.device.type
>   const next: boolean = !this.isOn()
>   let action: DeviceAction = { power: next ? 'on' : 'off' }
>   if (t === Const.DEV_CURTAIN) {
>     action = { openPercent: next ? 100 : 0 }
>   } else if (t === Const.DEV_PUMP) {
>     action = { watering: next ? 1 : 0 }
>     if (next) action.duration = this.device.status.duration ?? 10
>   } else if (t === Const.DEV_LOCK) {
>     action = { locked: next ? 0 : 1 }
>   }
>   const res = await DeviceApi.control(this.device.id, action)
>   // …成功则 this.device = res.data; this.onChanged()
> }
> ```
>
> 另外 `Format.deviceStatusText()` 本次补上了可调功能的摘要（空调的模式与风速、灯的色温、
> 插座的功率与累计用电、门禁的常开模式），**卡片不点进去也能看到当前设置**。

> 📄 **文件**：`smarthome_app/entry/src/main/ets/view/DeviceCard.ets` ｜ **负责人**：D（前端页面）

```typescript
// smarthome_app/entry/src/main/ets/view/DeviceCard.ets
import { router } from '@kit.ArkUI'
import { Device } from '../model/Device'
import { DeviceApi } from '../api/DeviceApi'
import { Const, deviceTypeName } from '../common/Const'
import { Format } from '../common/Format'

@Component
export struct DeviceCard {
  @Prop device: Device                 // @Prop：父组件传值，本组件内可改
  onChanged: () => void = () => {}     // 控制成功后通知父组件刷新

  /** 是否处于开启状态 */
  private isOn(): boolean {
    return this.device.status.power === 'on'
  }

  /** 点击开关圆点：发控制请求，用服务端返回的状态覆盖本地 */
  async togglePower() {
    const nextPower: string = this.isOn() ? 'off' : 'on'
    const res = await DeviceApi.control(this.device.id, { power: nextPower })
    if (res.code === 200 && res.data) {
      this.device = res.data          // 以服务端为准，避免本地状态错乱
      this.onChanged()
    }
  }

  build() {
    Column({ space: 6 }) {
      Row() {
        Text(deviceTypeName(this.device.type))
          .fontSize(12).fontColor(Const.TEXT_SUB)
        Blank()
        // 所有设备类型都有开关圆点（2026-09 起已无"只读传感器"类型）
        Circle({ width: 12, height: 12 })
          .fill(this.isOn() ? Const.SUCCESS : '#CCCCCC')
          .onClick(() => this.togglePower())
      }.width('100%')

      Text(this.device.name)
        .fontSize(14).fontWeight(FontWeight.Medium)
        .fontColor(Const.TEXT_MAIN)
        .maxLines(1).textOverflow({ overflow: TextOverflow.Ellipsis })
        .width('100%')

      Text(Format.deviceStatusText(this.device.type, this.device.status))
        .fontSize(12).fontColor(Const.TEXT_SUB)
        .width('100%')
    }
    .padding(14)
    .backgroundColor(Const.CARD_BG)
    .borderRadius(Const.CARD_RADIUS)
    .alignItems(HorizontalAlign.Start)
    // 点卡片进详情页
    .onClick(() => {
      router.pushUrl({ url: 'pages/device/DeviceDetailPage', params: { deviceId: this.device.id } })
    })
  }
}
```

### 6.4 设备详情页 DeviceDetailPage.ets —— 按设备类型渲染不同控件

> **2026-09 变更**：
> ① 详情页只处理**可控设备**（灯 / 空调 / 插座 / 窗帘 / **水泵 / 门禁**）。
> 温湿度计已移除，环境数据不在设备详情页展示，统一放首页的 `EnvironmentPanel`（见 6.19）。
> 因此 `statusHero()` 里不再有 `temp_sensor` 分支。
> ② 开关按钮**不是无条件渲染**了 —— 按类型分三档：
>
> | 类型 | 渲染哪个按钮 | 为什么 |
> |------|-------------|--------|
> | `curtain` | 不渲染（面板里有「全开/全关」+ 滑杆） | 避免 `power` 与 `openPercent` 打架 |
> | `pump` | `waterButton()`「开始浇水 / 停止浇水」 | 发 `watering`，语义是浇水而非通电 |
> | `lock` | `lockButton()`「上锁 / 开锁」（注意按钮文字与动作**反着**） | 发 `locked`，卡片开关"开"= 开锁 |
> | 其余 | `powerButton()`「打开 / 关闭」 | 通用开关 |
>
> ③ 新增两个专属面板：水泵（立即浇水时长、每日定时浇水、水箱水量只读进度条、预计停泵时间）
> 与门禁（上锁/开锁、电量、最近开关门、低电量提醒）。

> **2026-09-23 扩展**：把 6 类设备的可调基础功能补全 ——
> 这些字段后端状态里**本来就有**，只是前端一直没做 UI，用户以为"空调只能调温度"。
>
> | 类型 | 本次新增的面板内容 |
> |------|------------------|
> | `light` | 亮度滑杆 + **色温**（暖光 2700 / 自然光 4000 / 冷白光 6500，带色点预览） |
> | `ac` | **模式**（制冷·制热·除湿·送风·自动）、**风速**（自动·低·中·高）、**扫风**（关闭·上下·左右·上下+左右）、温度 **−/+ 步进按钮** + 滑杆 |
> | `socket` | 实时功率 / 累计用电 / 额定功率（只读展示，后端每分钟计量） |
> | `curtain` | 开合滑杆 + **全开 / 半开 / 全关** 快捷按钮 |
> | `lock` | 上锁 / 开锁 + **常开模式**开关 + 电量 + 最近开关门 |
> | 全部（水泵除外） | **每日定时开 / 关**（胶囊选项 + 当前定时摘要） |
>
> **两个实现要点（务必照做）**：
>
> ① **选项行用「方法现算 + ForEach」，不要用 `@Builder` 传值** ——
> `@Builder` 的参数是**值快照**，状态变了 UI 不会刷新（手册 5.0 踩坑）。
> 项目里的做法是把选项行抽成 `chipRow(options, kind)`：参数只传"选项数组 + 类别名"，
> 选中判断走 `this.currentStr(kind)`、点击下发走 `this.pickStr(kind, ...)` ——
> 每次渲染都取最新状态，不会僵住。ForEach 的 key 必须拼上选中态：
>
> ```typescript
> }, (opt: DeviceOption) => `${kind}_${opt.value}_${this.currentStr(kind) === opt.value}`)
> ```
>
> ⚠️ **选项数组有两种类型，别传错**：`common/DeviceOptions.ets` 里，
> "取值是字符串"的选项声明为 `DeviceOption[]`（如 `AC_MODES` / `TIMER_TIMES` / `LIGHT_COLOR_TEMPS`），
> "取值是数字"的声明为 `NumberOption[]`（如 `AC_FAN_SPEEDS` / `AC_SWINGS`）。
> 详情页对应两个构造器 `chipRow(options: DeviceOption[], kind)` 与
> `numChipRow(options: NumberOption[], kind)`。ArkTS 是强类型、不做隐式兼容，
> **把 `NumberOption[]` 传给 `chipRow()` 会直接编译失败**（`10505001 ArkTS Compiler Error`
> → `Type 'number' is not assignable to type 'string'`）。本工程踩过一次，详见 `05_更新记录.md` §2.3。
>
> ② **定时文案按设备类型说人话**：同一个"定时开"，空调叫「开机」、窗帘叫「全开」、
> 门禁叫「开锁」、水泵叫「浇水」—— 由 `timerOnWord()` / `timerOffWord()` 按类型返回，
> 用户看到的是自己设备的语言，而不是抽象的"开 / 关"。
>
> 选项字典统一定义在 **`common/DeviceOptions.ets`**
> （`AC_MODES` / `AC_FAN_SPEEDS` / `AC_SWINGS` / `LIGHT_COLOR_TEMPS` / `TIMER_TIMES`，
> 以及 `acModeName()` 这类"取值 → 中文"的转换函数）；设备卡片的状态文案也复用它（见 6.3）。
>

```typescript
  private loading: boolean = false    // 防重入：上一轮没回来就跳过
  private dragging: boolean = false   // 是否正在拖滑杆：拖动时不让轮询覆盖界面

  aboutToAppear() {
    // 从路由参数拿到设备 id
    const params = router.getParams() as DetailParams
    this.deviceId = params.deviceId
    this.loadDetail()
    // 每 5 秒静默刷新一次：空调等设备的状态可能被场景/定时任务改动，
    // 不轮询的话，停在详情页看大数字永远不动，像"坏了一样"。
    this.timerId = setInterval(() => {
      this.loadDetail(true)
    }, 5000)
  }

  aboutToDisappear() {
    // @Entry 页面 router.back() 时会触发，必须清掉定时器
    if (this.timerId !== -1) {
      clearInterval(this.timerId)
      this.timerId = -1
    }
  }

  /**
   * 拉取设备详情
   * @param silent 轮询用：拖滑杆时跳过本次，避免滑杆被服务端值"拽走"
   */
  async loadDetail(silent: boolean = false) {

      } else if (res.code === 401) {

      }
    } finally {
      this.loading = false
    }
  }

    if (this.timerId !== -1) {
      clearInterval(this.timerId)
      this.timerId = -1
    }
  }
```

```typescript
// smarthome_app/entry/src/main/ets/pages/shop/CartPage.ets
import { router } from '@kit.ArkUI'
import { ShopApi } from '../../api/ShopApi'
import { CartItem } from '../../model/Shop'
import { Const } from '../../common/Const'
import { Format } from '../../common/Format'
import { NumberStepper } from '../../view/NumberStepper'
import { EmptyView } from '../../view/EmptyView'

@Entry
@Component
struct CartPage {
  @State items: CartItem[] = []

  aboutToAppear() {
    this.load()
  }

  async load() {
    const res = await ShopApi.cartList()
    if (res.code === 200 && res.data) {
      // checked 是前端本地状态，默认全选
      this.items = res.data.map((item: CartItem) => {
        item.checked = true
        return item
      })
    }
  }

  /** 修改数量：先改本地再同步后端，体验更顺滑 */
  async changeQuantity(item: CartItem, quantity: number) {
    item.quantity = quantity
    this.items = this.items.slice()          // 重新赋值触发 UI 刷新
    await ShopApi.updateCart(item.id, quantity)
  }

  async removeItem(item: CartItem) {
    const res = await ShopApi.removeCart(item.id)
    if (res.code === 200) this.load()
  }

  /** 已勾选商品总价 */
  totalAmount(): number {
    let total: number = 0
    this.items.forEach((item: CartItem) => {
      if (item.checked) total += item.price * item.quantity
    })
    return total
  }

  selectedCount(): number {
    return this.items.filter((item: CartItem) => item.checked).length
  }

  build() {
    Column() {
      Row() {

                  .borderRadius(8).backgroundColor('#F5F5F5').objectFit(ImageFit.Contain)
```

```typescript
// smarthome_app/entry/src/main/ets/pages/shop/OrderConfirmPage.ets
import { router } from '@kit.ArkUI'
import { ShopApi } from '../../api/ShopApi'
import { UserApi } from '../../api/UserApi'
import { CartItem } from '../../model/Shop'
import { Address } from '../../model/User'
import { Const } from '../../common/Const'
import { Format } from '../../common/Format'

interface ConfirmParams {
  goodsId?: number       // 立即购买时传
  quantity?: number
  cartItems?: string     // 购物车结算时传（JSON 字符串）
}

@Entry
@Component
struct OrderConfirmPage {
  @State address: Address | null = null
  @State items: CartItem[] = []
  @State submitting: boolean = false
  private params: ConfirmParams = {}

  aboutToAppear() {
    this.params = router.getParams() as ConfirmParams
    this.loadAddress()
    this.buildItems()
  }

  async loadAddress() {
    const res = await UserApi.addressList()
    if (res.code === 200 && res.data && res.data.length > 0) {
      // 优先取默认地址
      const def = res.data.find((a: Address) => a.isDefault === 1)
      this.address = def ?? res.data[0]
    }
  }

  /** 组装待下单商品：来自购物车 */
  buildItems() {
    if (this.params.cartItems) {
      this.items = JSON.parse(this.params.cartItems) as CartItem[]
    }
  }

    let total: number = 0
    this.items.forEach((item: CartItem) => total += item.price * item.quantity)
    return total

      return

      return

      return { goodsId: item.goodsId, quantity: item.quantity }
    })
    const res = await ShopApi.createOrder(this.address!.id, orderItems)
    this.submitting = false

    if (res.code === 200 && res.data) {
      const order = res.data
      // 创建成功 → 立刻调"模拟支付"接口
      const payRes = await ShopApi.payOrder(order.id)
      if (payRes.code === 200) {
        router.replaceUrl({
          url: 'pages/shop/PayResultPage',
          params: { orderNo: order.orderNo, amount: order.totalAmount }
        })
      }
    }
  }

  build() {
    Column() {
      Row() {
        Text('‹ 返回').fontSize(16).onClick(() => router.back())
        Blank()
        Text('确认订单').fontSize(16).fontWeight(FontWeight.Medium)

      Scroll() {
        Column({ space: Const.CARD_GAP }) {
          // 收货地址

            Column({ space: 4 }) {
              if (this.address !== null) {
                Text(`${this.address!.receiver}　${this.address!.phone}`).fontSize(14)
                Text(`${this.address!.region} ${this.address!.detail}`)
                  .fontSize(12).fontColor(Const.TEXT_SUB)
              } else {
                Text('还没有收货地址').fontSize(14).fontColor(Const.TEXT_SUB)
                Text('点右侧按钮添加').fontSize(12).fontColor(Const.TEXT_SUB)
              }
            }.alignItems(HorizontalAlign.Start).layoutWeight(1)
            Text('管理').fontSize(13).fontColor(Const.BRAND)
              .onClick(() => router.pushUrl({ url: 'pages/mine/SettingsPage' }))
          }
          .width('100%').padding(16)
          .backgroundColor(Const.CARD_BG).borderRadius(Const.CARD_RADIUS)

          // 商品清单
          Column({ space: 12 }) {
            ForEach(this.items, (item: CartItem) => {
              Row({ space: 10 }) {
                Image($r('app.media.img_placeholder')).width(60).height(60)
                  .borderRadius(8).backgroundColor('#F5F5F5').objectFit(ImageFit.Contain)
                Column({ space: 4 }) {
```

```typescript
import { UserInfo } from '../../model/User'
import { Const } from '../../common/Const'
import { TokenStore } from '../../common/TokenStore'

@Component
export struct MinePage {
  @State userInfo: UserInfo | null = null
  @State isLogin: boolean = false

  /**
   * 来自 Index 的刷新信号（见 6.1 节 Index.ets 里 refreshTick 的注释）。
   *
   * Tab 子页面没有 onPageShow，aboutToAppear 又只在首次创建时跑一次，
   * 所以「登录 → router.back() 回到我的页」时本组件不会自动刷新，
   * isLogin 会一直停在登录前的 false，看起来就像"登录没成功"。
   * @Prop 负责父→子单向同步，@Watch 负责在信号变化时重新拉数据，两个必须成对出现。
   */
  @Prop @Watch('onRefreshTick') refreshTick: number = 0

  /** 刷新信号变化时重新拉登录态 */
  onRefreshTick() {
    this.refresh()
  }

  // 首次创建时也要拉一次（此时 @Watch 还没被触发过）
  aboutToAppear() {
    this.refresh()
  }

  /** 刷新登录态与用户信息 */
  async refresh() {
    this.isLogin = TokenStore.isLogin()
    if (this.isLogin) {
      const res = await UserApi.info()
      if (res.code === 200 && res.data) {
        this.userInfo = res.data
      } else {
        // 请求失败（典型是 token 失效返回 401）：
        // HttpClient 已经清掉本地 token，这里必须同步 UI 状态，
        // 否则会停在"显示已登录、但一个数据都没有"的假象里。
        this.userInfo = null
        this.isLogin = TokenStore.isLogin()
      }
    } else {
      this.userInfo = null      // 退出登录后清空，避免残留上一个用户数据
    }
  }
```

```typescript
  @State password: string = ''
  @State confirmPassword: string = ''
  @State loading: boolean = false

  /** 前端校验：能提前拦掉的错误不要浪费一次请求 */
  checkInput(): string {
    if (this.username.length < 3) return '账号至少 3 位'
    if (this.password.length < 6) return '密码至少 6 位'
    if (this.password !== this.confirmPassword) return '两次输入的密码不一致'

    if (err.length > 0) {

      return
    }

      const loginRes = await UserApi.login(this.username, this.password)
      if (loginRes.code === 200 && loginRes.data) {

        await TokenStore.save(loginRes.data, name)
      }
```

> 明细是快照、进页后不会变，ForEach 的 key 用 `goodsId + index` 就够
> （**与设备卡相反**——设备卡 key 必须拼会变的数据，见 5.0 ②）。

### 6.19 view/EnvironmentPanel.ets —— 房间环境监测面板（本项目新增核心组件）

> **需求来源**：房间的环境监测要覆盖 **温度 / 湿度 / 空气质量 / 二氧化碳 / 烟雾报警** 五项，
> **厨房在此基础上还要能检测燃气是否泄漏**。原先靠"温湿度计设备"读数值的做法已废弃
> （温湿度计 `temp_sensor` 类型已从产品和设备定义中移除）。

**三个必须理解的设计点：**

| 设计点 | 说明 |
|--------|------|
| 数据是**房间的属性**，不是设备的状态 | 环境数据来自 `room_environment` 表，通过 `HomeOverview.environments` 下发。所以环境面板挂在首页、跟着**房间切换**变，而不是挂在某台设备详情页 |
| **厨房自动判定** | 后端按房间名匹配「厨 / 燃气 / 灶」，命中则 `hasGas=1`。前端**只认 `hasGas` 字段**，不自己判断房间名 —— 判定口径只维护一份 |
| **等级文案由后端算** | `temperatureLevel` / `airLevel` / `co2Level` 等中文等级直接来自后端，前端只负责显示和上色。**前端不重算阈值**，避免两端口径跑偏 |

**组件骨架：**

> 📄 **文件**：`smarthome_app/entry/src/main/ets/view/EnvironmentPanel.ets` ｜ **负责人**：D（前端页面）

```typescript
// smarthome_app/entry/src/main/ets/view/EnvironmentPanel.ets
import { RoomEnv } from '../model/Device'
import { Const } from '../common/Const'
import { Format } from '../common/Format'

/** 一个指标格的展示数据（纯前端拼装，用于 ForEach 渲染） */
interface EnvMetricCell {
  key: string        // 指标标识，同时作为 ForEach 的 key 前缀
  label: string      // 中文名：温度 / 二氧化碳 / 燃气泄漏 …
  value: string      // 主数值文本（已格式化，含单位）
  level: string      // 状态文案：舒适 / 优 / 报警 …
  color: string      // 数值颜色：正常绿 / 提醒橙 / 告警红
}

@Component
export struct EnvironmentPanel {
  /** 当前房间的环境数据；父组件未拿到数据时传 null，面板显示占位 */
  @Prop env: RoomEnv | null = null
  /** 点"立即刷新"的回调：由父组件发起请求（本组件不发请求，保持分层干净） */
  onRefresh: () => void = () => {}
  /** 刷新中：按钮置灰防连点 */
  @Prop refreshing: boolean = false

  /** 组装指标格列表 —— 5 项基础指标 + 厨房额外的燃气项 */
  private metrics(): EnvMetricCell[] {
    const env = this.env
    if (env === null) return []
    const list: EnvMetricCell[] = []

    // ① 温度：18~28℃ 舒适
    list.push({
      key: 'temperature',
      label: '温度',
      value: `${env.temperature}℃`,
      level: env.temperatureLevel,
      color: (env.temperature < 18 || env.temperature > 28) ? Const.ENV_WARN : Const.ENV_OK
    })

    // ② 湿度：30~70% 舒适
    list.push({
      key: 'humidity', label: '湿度', value: `${env.humidity}%`, level: env.humidityLevel,
      color: (env.humidity < 30 || env.humidity > 70) ? Const.ENV_WARN : Const.ENV_OK
    })

    // ③ 空气质量：AQI <=100 优良，>150 污染
    list.push({
      key: 'aqi', label: '空气质量', value: `${env.aqi}`, level: env.airLevel,
      color: env.aqi > 150 ? Const.ENV_ALARM : (env.aqi > 100 ? Const.ENV_WARN : Const.ENV_OK)
    })

    // ④ 二氧化碳：<=1500ppm 正常，超过建议通风
    list.push({
      key: 'co2', label: '二氧化碳', value: `${env.co2} ppm`, level: env.co2Level,
      color: env.co2 > 1500 ? Const.ENV_ALARM : (env.co2 > 1000 ? Const.ENV_WARN : Const.ENV_OK)
    })

    // ⑤ 烟雾报警：>50ppm 报警
    list.push({
      key: 'smoke', label: '烟雾报警', value: `${env.smoke} ppm`,
      level: env.smokeAlarm === 1 ? '⚠ 烟雾报警' : '正常',
      color: env.smokeAlarm === 1 ? Const.ENV_ALARM : Const.ENV_OK
    })

    // ⑥ 燃气泄漏：**仅厨房**（后端 hasGas=1 才返回燃气数值），>200ppm 泄漏告警
    if (env.hasGas === 1) {
      const gasValue: string = env.gas === undefined ? '--' : `${env.gas}`
      list.push({
        key: 'gas', label: '燃气泄漏', value: `${gasValue} ppm`,
        level: env.gasAlarm === 1 ? '⚠ 燃气泄漏' : '正常',
        color: env.gasAlarm === 1 ? Const.ENV_ALARM : Const.ENV_OK
      })
    }
    return list
  }

  /** 单个指标格（@Builder）：固定尺寸，保证 2 列网格对齐 */
  @Builder
  metricCell(cell: EnvMetricCell) {
    Column({ space: 3 }) {
      Text(cell.label).fontSize(11).fontColor(Const.TEXT_SUB).width('100%')
      Text(cell.value).fontSize(17).fontWeight(FontWeight.Medium).fontColor(cell.color)
        .maxLines(1).textOverflow({ overflow: TextOverflow.Ellipsis }).width('100%')
      Text(cell.level).fontSize(10).fontColor(cell.color)
        .maxLines(1).textOverflow({ overflow: TextOverflow.Ellipsis }).width('100%')
    }
    .alignItems(HorizontalAlign.Start)
    .padding({ top: 10, bottom: 10, left: 12, right: 12 })
  }

  build() {
    Column({ space: 10 }) {
      // ---------- 标题行：房间名 + 立即刷新 ----------
      Row() {
        Text('环境监测').fontSize(15).fontWeight(FontWeight.Medium).fontColor(Const.TEXT_MAIN)
        if (this.env !== null) {
          Text(` · ${this.env.roomName}`).fontSize(12).fontColor(Const.TEXT_SUB)
        }
        Blank()
        Text(this.refreshing ? '采样中…' : '立即刷新')
          .fontSize(12).fontColor(this.refreshing ? Const.TEXT_SUB : Const.BRAND)
          .onClick(() => {
            if (this.refreshing) return    // 刷新中不响应，避免连点打出一串请求
            this.onRefresh()
          })
      }.width('100%')

      if (this.env === null) {
        // 未登录 / 暂无房间：不渲染任何数值，避免显示一堆 0 让人误会
        Text('暂无环境数据').fontSize(12).fontColor(Const.TEXT_SUB).width('100%')
      } else {
        // ---------- 告警条：只在有告警时出现（红色，最醒目的位置） ----------
        if (this.env.alarmCount > 0) {
          Row({ space: 6 }) {
            Text('⚠').fontSize(13).fontColor(Color.White)
            Text(Format.envAlarmText(this.env))
              .fontSize(12).fontColor(Color.White).layoutWeight(1)
          }
          .width('100%').padding({ left: 12, right: 12, top: 8, bottom: 8 })
          .backgroundColor(Const.ENV_ALARM).borderRadius(Const.RADIUS_SMALL)
        }

        // ---------- 指标网格：2 列，厨房自动多出"燃气泄漏"一格 ----------
        Grid() {
          ForEach(this.metrics(), (cell: EnvMetricCell) => {
            GridItem() { this.metricCell(cell) }
          }, (cell: EnvMetricCell) => {
            // 【关键】key 必须拼上"会变的数值"，否则轮询拿到新数据也刷不上屏
            return `${cell.key}_${cell.value}_${cell.level}`
          })
        }
        .columnsTemplate('1fr 1fr').columnsGap(1).rowsGap(1)
        .backgroundColor(Const.DIVIDER)      // 靠背景色透出 1px 网格线
        .borderRadius(Const.RADIUS_SMALL).clip(true)
        .height(this.metrics().length <= 4 ? 140 : 210)
      }
    }
    .alignItems(HorizontalAlign.Start)
    .width('100%').padding(16)
    .backgroundColor(Const.CARD_BG).borderRadius(Const.CARD_RADIUS)
  }
}
```

**⚠️ 这个组件踩过的两个坑，改代码前务必看：**

1. **ForEach 的 key 必须拼数值**（`${cell.key}_${cell.value}_${cell.level}`）。
   如果图省事只写 `cell.key`，轮询拿到新数值时 key 没变，框架会**复用旧组件**，
   表现就是「数字永远停在第一次看到的值」。
2. **指标格不要抽成"按值传参的 @Builder"再在外面判断**。`@Builder` 按值传参会**冻住首帧**，
   状态变了也不重建。这里用的是 `ForEach(this.metrics(), ...)` —— 每次 build 都重新组装数组，
   数据变 → 数组变 → key 变 → 渲染更新，链路是通的。

**厨房房间看起来不一样，是正常的**：切到「厨房」时，指标格从 5 个变 6 个（多出「燃气泄漏」），
网格高度自动从 140 变 210。普通房间后端直接返回 `gas: null, hasGas: 0`，面板不渲染这一格。

### 6.20 广告启动页 AdPage.ets（打开 App 的第一屏）

> 对应文件：`pages/AdPage.ets`、`common/AppFlag.ets`，以及 `pages/Index.ets` 开头那段跳转。
> 广告图：`resources/base/media/img_ad.png`（AI 生成，`$r('app.media.img_ad')` 引用）。

**需求拆解**（四条，逐条对应实现）：

| 需求 | 实现 |
|------|------|
| 打开软件就是广告 | 冷启动后第一件事跳 AdPage（见下面「启动页是谁」） |
| 15 秒自动进首页 | `setInterval` 每秒 `seconds--`，减到 0 调 `enterApp()` |
| 能跳过 | 右上角胶囊按钮，点击直接 `enterApp()` |
| 跳转后销毁、无法返回 | `router.replaceUrl`（**不是** `pushUrl`）+ `onBackPress` 返回 `true` |

**启动页是谁？这是本节最容易被误解的一点。**

`main_pages.json` 里 `pages/AdPage` 排在第一位，**但那个顺序不决定首屏**。
真正决定首屏的是 `entryability/EntryAbility.ets` 里的这一行：

```typescript
// EntryAbility.ets · onWindowStageCreate
windowStage.loadContent('pages/Index', (err) => { ... })
```

所以本项目的做法是：**首屏仍是 `pages/Index`**，由 Index 在 `aboutToAppear` 里立刻
`replaceUrl` 到广告页。`main_pages.json` 的排序只是为了让页面能被路由到，**两个地方的页面名必须都写对**。

```typescript
// pages/Index.ets · aboutToAppear 开头
if (!AppFlag.adShown) {
  AppFlag.adShown = true
  router.replaceUrl({ url: 'pages/AdPage' })
  return            // 本次不做后面的 TokenStore.init()，等真正进首页那次再做
}
```

**为什么必须用 `replaceUrl` 而不是 `pushUrl`：**

- `pushUrl`：页面栈变成 `[Index, AdPage]`。广告结束后无论怎么跳，用户一按返回就退回 **Index 这个空壳**，
  等于"广告页没销毁"。
- `replaceUrl`：AdPage 直接**顶替掉** Index，栈里只剩 AdPage；广告结束再 `replaceUrl` 回 Index，
  栈里只剩 Index —— 在首页按返回键就是退出 App，绝不回到广告页。

**`common/AppFlag.ets` 是干什么的（不看会产生死循环）：**

标志必须写成**类的 static 字段**，不能写成 Index 的成员变量：

```typescript
export class AppFlag {
  static adShown: boolean = false     // 进程内只有一份
}
```

因为 `replaceUrl` 会**销毁旧的 Index 实例**，成员变量跟着实例一起重置 →
新的 Index 又发现"广告没弹过" → 再跳一次广告 →
`Index → 广告 → Index → 广告 …` 无限循环，表现就是**屏幕一直在闪广告页**。
`static` 字段属于类本身，与页面实例生死无关，才能保证「一次冷启动只弹一次广告」；
重启 App 后进程重建，又会正常弹一次。

**其他要注意的点：**

1. `aboutToDisappear` 里必须 `clearInterval`，否则广告页销毁后定时器还活着。
2. `onBackPress` 返回 `true` 表示"吞掉返回键"，广告期间的返回/侧滑都不会退出页面。
3. 广告图放 `resources/base/media/` 下，用 `alt + Enter` 或直接写 `$r('app.media.img_ad')`；
   文件名全小写带下划线（`img_ad`），**不能有大写字母和连字符**。
4. 广告页也在 `main_pages.json` 里登记着 —— 漏登记会直接报 `page not found`，白屏。

## 第七章 常见问题排查（前端）

> 下面分三类：**A. 编译不过** → **B. 跑起来不对** → **C. 改了没生效**。
> 遇到问题先想清楚属于哪一类，能大幅缩短排查时间。详细正反例见 5.0 节。

### 7.1 A 类：编译不过（`COMPILE RESULT:FAIL`）

| 现象 | 原因与解决 |
|------|-----------|
| `arkts-no-untyped-obj-literals`<br>Object literal must correspond to some explicitly declared class or interface | 把裸对象字面量 `{ ... }` 直接写进了 api 调用参数（**最常见，25 个 ERROR 里占 20 个**）。先在 api 文件里声明 `XxxParam` interface，再 `const body: XxxParam = { ... }` 传进去 |
| `arkts-no-any-unknown`<br>Use explicit types instead of "any","unknown" | `ForEach` 的回调参数没标类型。两个回调都要标：`ForEach(list, (item: Device) => {...}, (item: Device) => item.id.toString())` |
| `arkts-no-implicit-return-types`<br>Function return type inference is limited | 箭头函数隐式返回了 Promise，如 `onChanged: () => this.loadAsync()`。用花括号包住函数体：`onChanged: () => { this.loadAsync() }` |
| `Cannot find name 'XXX'` | 忘了 import 该类型。文件头补 `import { XXX } from '../model/...'`。**注意：并发改文件时 import 行最容易丢**，报这个错先看文件头 |
| 数组用 `object[]` 声明报错 | 换成具体类型，如 `OrderItemParam[]`；`map` 的回调里要显式声明元素类型再 return |
| 报错数量很多（十几二十条） | 先改**第一条**再重新编译。ArkTS 一个错会级联出一串，常常改完第一条就归零 |

### 7.2 B 类：跑起来不对

| 现象 | 原因与解决 |
|------|-----------|
| 请求全失败、提示网络异常 | 1) `Env.BASE_URL` 的 IP 不对（用 `ipconfig` 查）2) 手机与电脑不在同一 WiFi 3) 后端没启动 4) Windows 防火墙拦了 8080 端口 |
| `page not found` | 页面没登记到 `main_pages.json`；5 个 Tab 页由 `Index.ets` 内嵌承载，**不需要**登记 |
| 数据不刷新 | 数组/对象改了但没重新赋值。ArkTS 里改数组元素后要 `this.arr = this.arr.slice()` |
| **轮询正常、后端数据也在变，但列表项的状态文字永远不动** | **ForEach 的 key 只用了 id**。key 相同 ArkUI 就复用旧组件、不同步新数据。把会变的字段拼进 key（见 5.0 ② 的踩坑记录），首页设备卡片就是这么修的 |
| 页面退出后还在发请求 | `aboutToDisappear` 里没 `clearInterval` |
| **切到别的 Tab 后，首页还在后台发请求** | Tabs 子页切走**不销毁**，定时器还在跑。要给 HomePage 传 `visible`（见 6.2），切走时 `stopPolling()` |
| **一直弹"登录已过期"，像弹幕** | 401 提示没节流，被 5 秒轮询反复触发。按 4.3.1 的三条纪律改：只有"本地本来带 token"才算过期 + 提示节流 + 未登录不发需登录的请求 |
| **没登录也一直弹"登录已过期"** | 把"未登录时的 401"错当成"过期"了。判断逻辑要写成 `const hadToken = TokenStore.isLogin(); if (!hadToken) return` |
| 所有接口返回 401 | 1) 请求头没带 token，检查 `TokenStore.init()` 是否被调用 2) token 真过期（默认 7 天）3) **后端进程是旧的，没重启**（见后端手册 1.6 节，本项目真实踩过） |

### 7.3 C 类：改了没生效（最容易绕远路的一类）

**这一类的共同点：不是代码写错了，是"改的东西没被读到"。按下面顺序排除，别跳步。**

| 现象 | 原因与解决 |
|------|-----------|
| 明明改了代码，重新编译报错却和之前一模一样 | ① 文件**没保存**（标签页上的 `*` 号没消失）② hvigor 守护进程缓存旧快照。先 `Ctrl+S`，再 `Build → Clean Project`；命令行编译加 `--no-daemon` |
| 报错行号对不上、已修好的错又冒出来 | 同上，缓存问题。见 5.0.2 |
| 改了一个文件，结果另一个文件的改动"凭空消失" | 对同一文件并发改动，后写的覆盖了先写的。纪律：**一次只改一个文件，改完核对落盘再改下一个**，同文件多处修改串行做（见 5.0.1） |
| 找不到自己改的是哪个工程 | 目录命名不一致会出现 `smarthome_app` / `smarthome-app` **两套目录**。在项目根执行 `dir /b` 确认，只保留有代码的那一套（见《01_总方案.md》第十一章踩坑 1） |
| **代码明明改了，App 里行为却没变** | 装到手机/模拟器上的还是旧 hap。DevEco 里要重新 **Run（重新安装）** 才算，只 Build 不安装没用。同一个坑在后端更常见：**Java 代码改了必须重启进程**，JVM 只加载一次 class（见后端手册 1.6 节） |
| 提交后别人拉下来编译不过 | 提交前没编译。**先 `assembleHap` 通过再 commit**（见 5.0.4） |

> **排查口诀**：C 类问题的第一步永远是**确认磁盘上的文件真的是新的**——
> 保存、找到正确的工程目录、清缓存，三步做完再看代码对不对。
