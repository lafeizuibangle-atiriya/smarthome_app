# 米家风格智慧家居 App 开发手册（后端 · Spring Boot）

> 配套《01_总方案.md》与《02_开发手册_前端.md》使用。
> 严格三层：**控制层 Controller → 业务层 Service → 数据层 Mapper**。
> 环境：Spring Boot 3 + MyBatis-Plus + MySQL 8 + Hutool
>
> ⚠️ **改配置前先看 1.4 节与 1.5 节**。项目落地时"改完密码仍然 `Access denied`"绕了很久，
> 根因是两个：① 编辑器没保存到磁盘；② 运行期读的是 `target/classes/` 里的旧副本。
> **遇到"改了没用"直接跳到第十章 10.3 节。**
>
> 📌 **命名约定**：目录、文件统一用下划线 `_`，不用连字符 `-`（工程目录是 `smarthome_server`）。
> 📌 **同一时间只启动一个后端实例**（有两个定时任务在同一进程内）。

### 1.2 启动类

> 📄 **文件**：`smarthome_server/src/main/java/com/smarthome/SmartHomeApplication.java` ｜ **负责人**：A（后端架构）

```java
package com.smarthome;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableScheduling;

/**
 * 启动类 —— 整个后端的唯一入口（已有，不用改）。
 *
 * @SpringBootApplication 一个注解顶三件事：
 *   ① 自动配置：按 pom 里的 starter 自动装配数据源、MVC、Jackson……
 *   ② 组件扫描：从本类所在包 `com.smarthome` **向下**扫 @Controller / @Service / @Mapper / @Component
 *      → 所以所有业务类都必须放在 com.smarthome 包下。放到包外不会报错，只是**不会被加载**
 *        （典型症状：类明明写了，接口却 404 / 注入报 NoSuchBeanDefinition）。
 *   ③ 兼作配置类（等价 @Configuration）。
 *
 * @EnableScheduling 开启 @Scheduled 定时任务。**少了这一句，三个定时任务全部静默不执行**：
 *   SensorSimTask（30 秒一次环境采样）、SceneTimedTask（每分钟扫定时场景）、WaterTimedTask（每分钟扫水泵）。
 *   症状是"接口都正常，但环境数值永远不动" —— 遇到先回来看这里，别去怀疑业务代码。
 *
 * 【怎么启动】IDEA 里直接 Run/Debug 本类；或命令行 `mvnw.cmd spring-boot:run`。
 * 【铁律】同一时间只允许跑一个实例（两个实例会让定时任务双跑，见 1.6 节）。
 */
@SpringBootApplication
@EnableScheduling
public class SmartHomeApplication {
    public static void main(String[] args) {
        // 依次做：读配置 → 建数据库连接池 → 注册所有 Controller → 起内嵌 Tomcat(8080) → 开始调度定时任务
        SpringApplication.run(SmartHomeApplication.class, args);
    }
}
```

### 1.4 application.yml（四处别写错：密码、时区、驼峰映射、SQL 日志）

> 📄 **文件**：`smarthome_server/src/main/resources/application.yml` ｜ **负责人**：组长（环境统一）

```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/smart_home?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: "123456"                    # ← 改成你自己 MySQL 的密码，用双引号包住
    driver-class-name: com.mysql.cj.jdbc.Driver
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss      # 统一时间格式，App 端不用自己格式化
    time-zone: GMT+8

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true    # create_time 自动映射 createTime
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl   # 控制台打印 SQL，调试神器
  global-config:
    db-config:
      id-type: auto
```

**关于 `password` 这一行，有三条必须记住：**

1. **一定要改掉模板里的占位符文字。** 模板里如果还写着 `password: 你的密码`，
   Spring 会把「你的密码」当成真实密码去连数据库，结果就是
   `Access denied for user 'root'@'localhost' (using password: YES)`。
2. **用双引号把密码包起来。** YAML 里 `#` 是注释符，`:` 是键值分隔符。
   密码里有 `# @ ! :` 这类字符时，不加引号会被截断或解析错，报的错还是 `Access denied`，很难看出来。
3. **改完必须保存到磁盘并重新构建。** 这两件事经常被忽略，见 1.5 节。

### 1.5 【必读】改了配置为什么没生效：`target/classes` 机制

**这是项目落地时绕得最久的一个坑。** 现象：`application.yml` 里明明改成了正确密码，
启动日志却依然 `Access denied`。

原因是**两个独立的问题叠在一起**，必须分别排除：

#### 原因 A：编辑器没保存到磁盘

在 IDEA 里改完，标签页标题上会有一个 `*` 号，表示**改动只在编辑器内存里**，
磁盘上的文件还是旧的。程序启动读的是磁盘，自然读到旧值。

**怎么确认**（不要信任编辑器界面，直接看磁盘）：

```cmd
type D:\Code\smarthome_project\smarthome_server\src\main\resources\application.yml
```

看到 `password` 那行确实是新密码，才算保存成功。

#### 原因 B：运行期读的是 `target/classes/` 的副本

Maven 构建时会做两件事：

```
src/main/java/**.java        --编译-->  target/classes/**.class
src/main/resources/**        --复制-->  target/classes/**
```

**Spring Boot 运行时读的是 `target/classes/` 里的副本，不是 `src/main/resources/` 里的源文件。**
只改源文件不重新构建，副本还是旧的，跑起来就是旧配置。

| 目录 | 是什么 | 提交 Git |
|------|--------|----------|
| `src/main/resources/application.yml` | **源**配置，你编辑的那份 | ✅ 提交 |
| `target/classes/application.yml` | 构建时**复制**出来的副本，运行时真正读的 | ❌ 不提交 |
| `target/` | Maven 构建产物目录，可随时删，重新构建会再生 | ❌ 不提交 |

#### 正确的操作顺序（照做，别跳步）

1. 编辑器里改完 → `Ctrl+S` → 确认标签页的 `*` 号消失；
2. `type` 一下源文件，**肉眼确认磁盘内容已变**；
3. IDEA 里 `Build → Rebuild Project`（快捷键 **`Ctrl+F9`**）；
4. 再启动 `SmartHomeApplication`。

> **排查口诀：先确认磁盘，再怀疑缓存。**
> 顺序反了会绕很久——很多人一上来就 `mvn clean`、清 IDEA 缓存，其实压根是文件没保存。

### 1.6 启动与端口：只允许一个实例

**同一时间只能有一个后端进程。** 项目里有**四个**定时任务跑在同一进程内：

| 定时任务 | 频率 | 干什么 |
|----------|------|--------|
| `SensorSimTask` | 30 秒 | 让**每个房间的环境监测数值**小幅波动（模拟环境采样） |
| `SceneTimedTask` | 每分钟 | 扫描定时场景并执行 |
| `WaterTimedTask` | 每分钟 | **（2026-09 新增）** 扫描浇花水泵：到点自动开泵、到点自动停泵并扣减水箱水量 |
| `DeviceTimedTask` | 每分钟 | **（2026-09-23 新增）** 通用定时开关（6 类设备共用的 `timerOn`/`timerOff`）+ 插座用电计量 |

如果开了两个实例（IDEA 点了一次运行、命令行又 `mvnw.cmd spring-boot:run`，或端口没释放直接重启），
两个进程会同时写库：**环境数值双倍跳动、定时场景重复执行、水泵水量双倍扣减、插座用电量双倍累加**。

**启动方式二选一，不要同时用：**

```cmd
:: 方式一：IDEA 打开 smarthome_server 目录，运行 SmartHomeApplication（推荐）

:: 方式二：命令行用自带 Maven Wrapper（本机不用装 Maven）
cd smarthome_server
mvnw.cmd spring-boot:run
```

**端口被占用的排查：**

```cmd
netstat -ano | findstr :8080
```

拿到最后一列的 PID，去任务管理器结束该进程，或直接 `taskkill /PID <PID> /F`。

**验证启动成功**：浏览器打开 `http://localhost:8080/api/user/info`，返回
`{"code":401,"msg":"请先登录"}` 即可（这个接口需要登录，未带 token 时返回 401 是**预期**的；
能返回这段 JSON，就说明服务已启动、拦截器已生效）。

> ⚠️ 不要拿 `/api/product/categories` 这类**公开接口**做健康检查：它们不需要 token，
> 请求失败时你看到的是"连接被拒"而不是 401，判不出"服务起来了但没登录"这个中间态。
> 另外注意：**打任何不存在的路径，返回值都是 `code=500 服务器繁忙`（不是 404）**——
> Spring 找不到处理器时抛 `NoResourceFoundException`，被全局异常处理的兜底分支接住。
> 看到 500 先确认路径是不是写错了。

### 1.7 【必读】Java 代码改了，为什么必须重启进程

**JVM 只在启动那一刻加载 class 文件**，之后不会再去磁盘看源文件有没有变。
所以会出现这种最让人抓狂的现象：

> 代码明明改对了，编译也通过了，接口行为一点没变。

因为跑着的进程里，还是**启动那一刻加载进内存的旧 class**。

**判断依据**：比对「进程启动时间」和「class 编译时间」。**进程比 class 早，就是旧的。**

```powershell
# 1) 看 java 进程的启动时间
Get-CimInstance Win32_Process -Filter "Name = 'java.exe'" | Select-Object ProcessId, CreationDate
# 2) 看 class 的编译时间
Get-Item .\target\classes\com\smarthome\common\JwtUtil.class | Select-Object LastWriteTime
```

**正确姿势（IDEA）**：

| 操作 | 有用吗 |
|------|--------|
| 改完代码点 **⟳ Rerun**（或先 Stop 再 Run） | ✅ 这才是生效 |
| 只点 **Build / Ctrl+F9** | ⚠️ 只重新生成 `target/classes`，**不会**把新 class 装进已经跑着的 JVM |
| 只关掉模拟器/App 重开 | ❌ 后端进程没重启，等于没改 |

**本项目真实案例**：`JwtUtil.verifyToken()` 修好、编译通过、单测也过了，App 仍然登录失败。
原因是 8080 上跑的进程启动于 **15:26**，而修好的 `JwtUtil.class` 编译于 **15:46** —— 差 20 分钟。
重启一次即恢复。

**接口自测（不依赖 App，最快确认后端是否正确）**：

```bash
# 第 1 步：登录，从返回的 data 里取出 token 字符串
curl -X POST http://localhost:8080/api/user/login \
     -H "Content-Type: application/json" \
     -d "{\"username\":\"demo\",\"password\":\"123456\"}"

# 第 2 步：带上 token 请求需要登录的接口（注意请求头名字就叫 token，不是 Authorization）
curl http://localhost:8080/api/user/info -H "token: 上一步的token"
```

期望返回 `{"code":200,...,"data":{"nickname":"演示用户",...}}`。
**如果这里返回 401，就别去查 App 了** —— 问题在后端（先看进程有没有重启，再看 2.4 节的 JWT 两个坑）。

### 2.1 统一返回体

> 📄 **文件**：`smarthome_server/src/main/java/com/smarthome/common/Result.java` ｜ **负责人**：A（后端架构）

```java
// smarthome_server/src/main/java/com/smarthome/common/Result.java
package com.smarthome.common;

import lombok.Data;

/**
 * 统一返回体 —— 全项目所有接口的返回**永远是这三个字段**，App 端只写一套解析逻辑。
 *
 * 对应前端：`HttpClient.ets` 里的 interface ApiResponse<T>（字段名必须一模一样）。
 *
 *  code 约定（团队红线，别自创）：
 *     200 成功        → App 正常取 data
 *     400 业务错误    → msg 是给用户看的中文提示（如"库存不足"），App 直接用 toast 弹出
 *     401 未登录/过期 → App 收到后清登录态并跳登录页
 *     500 系统错误    → App 只说"服务器繁忙"，真实原因看后端控制台日志
 *
 * 为什么用泛型：`Result<UserInfoVO>`、`Result<List<DeviceVO>>` 都靠 T 表达，
 * App 端就能写成 `ApiResponse<UserInfo>` 而不用强转。
 */
@Data
public class Result<T> {
    private int code;        // 200 成功 / 400 业务错 / 401 未登录 / 500 系统错
    private String msg;      // 提示语，400 时直接展示给用户看
    private T data;          // 业务数据；无返回值的接口这里是 null

    /** 成功且带数据：return Result.ok(vo) */
    public static <T> Result<T> ok(T data) {
        Result<T> r = new Result<>();
        r.code = 200;
        r.msg = "success";
        r.data = data;
        return r;
    }

    /** 成功但没有数据体：注册、删除这类接口用。内部就是 ok(null) */
    public static <T> Result<T> ok() { return ok(null); }

    /**
     * 失败：一般由 GlobalExceptionHandler 自动调用，业务代码里很少手写。
     * 注意：业务错误优先用 `throw new BizException("提示语")`，让全局异常处理器统一包成 400，
     * Service 里就不会到处出现 `return Result.error(...)`（那是控制层的活）。
     */
    public static <T> Result<T> error(int code, String msg) {
        Result<T> r = new Result<>();
        r.code = code;
        r.msg = msg;
        return r;
    }
}
```

### 2.3 全局异常处理

> 📄 **文件**：`smarthome_server/src/main/java/com/smarthome/common/GlobalExceptionHandler.java` ｜ **负责人**：A（后端架构）

```java
// smarthome_server/src/main/java/com/smarthome/common/GlobalExceptionHandler.java
package com.smarthome.common;

import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 业务异常：把提示语原样给前端 */
    @ExceptionHandler(BizException.class)
    public Result<Void> handleBiz(BizException e) {
        return Result.error(400, e.getMessage());
    }

    /** 兜底：不暴露堆栈给客户端，只记日志 */
    @ExceptionHandler(Exception.class)
    public Result<Void> handleOther(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "服务器繁忙，请稍后再试");
    }
}
```

### 2.4 JWT 工具（Hutool，十行搞定 —— 但有两个坑必须避开）

> ⚠️ **这一节踩过坑，代码已修正，请不要用网上搜到的"简化版"覆盖它。**
> 两个坑的后果都是 **"登录接口返回 200 和 token，但之后所有需要登录的接口全部 401"**，
> 前端表现是「提示登录成功，实际没登进去」，极容易被误判成"请求没发到后端"。
> 详细复盘见《01_总方案.md》第十一章踩坑 10。

#### 坑 1：`verify()` 只验签名，**不验有效期**

Hutool 的 `JWT.verify()` 只校验签名对不对，**完全不看 `exp`**。
实测：手工造一个 `exp` 是昨天的 token，`verify()` 依然返回 `true`——过期 token 能一路畅通。

**正确写法**：用 `validate(0)`，它等于「验签名 + 验有效期」；参数 0 表示允许 0 秒时钟偏差。

#### 坑 2：`getPayload()` 取出的数字**不能直接强转 `Integer`**

`setPayload("userId", 1L)` 写进去的是 Long，但 Hutool 5.8.x 读出来的是
`cn.hutool.core.convert.NumberWithFormat`（`Number` 的子类，**不是** `Integer`）。

```java
// ❌ 这行会抛 ClassCastException
Integer userId = (Integer) JWT.of(token).getPayload("userId");
// NumberWithFormat cannot be cast to java.lang.Integer
```

更阴的是：它抛出的异常**正好被同一个方法里的 `catch (Exception e)` 吞掉**，
方法安静地返回 `null`，拦截器据此判定"未登录"→ 返回 401。
**控制台一行报错都没有**，所以极难查。

**正确写法**：先取成 `Number`，再 `longValue()`。

> 📄 **文件**：`smarthome_server/src/main/java/com/smarthome/common/JwtUtil.java` ｜ **负责人**：A（后端架构）

```java
// smarthome_server/src/main/java/com/smarthome/common/JwtUtil.java
package com.smarthome.common;

import cn.hutool.jwt.JWT;
import java.util.Date;

/** JWT 工具（Hutool 实现）：生成 / 校验 token */
public class JwtUtil {
    private static final String SECRET = "smarthome-secret-2024";   // 签名密钥
    private static final long EXPIRE = 7 * 24 * 3600 * 1000L;        // 7 天有效

    /** 生成 token，payload 里放 userId */
    public static String createToken(Long userId) {
        return JWT.create()
                .setPayload("userId", userId)
                .setExpiresAt(new Date(System.currentTimeMillis() + EXPIRE))
                .setKey(SECRET.getBytes())
                .sign();
    }

    /**
     * 校验并取出 userId；无效或过期返回 null。
     * 注意两处：① 用 validate(0) 而不是 verify()，否则过期 token 也能通过；
     *          ② payload 里的数字是 NumberWithFormat，必须先转 Number 再 longValue()。
     */
    public static Long verifyToken(String token) {
        try {
            if (token == null || token.isEmpty()) return null;

            JWT jwt = JWT.of(token).setKey(SECRET.getBytes());
            if (!jwt.validate(0)) return null;        // 签名 + 有效期，缺一不可

            Object raw = jwt.getPayload("userId");
            if (raw == null) return null;
            if (raw instanceof Number) return ((Number) raw).longValue();
            return Long.valueOf(raw.toString());
        } catch (Exception e) {
            // 任何解析异常都视为 token 无效（拦截器只认 null，别往外抛）
            return null;
        }
    }
}
```

**写完怎么自测**（不用启动整个工程，3 分钟能验完）：

```java
// 临时写个 main 跑一下，6 种情况都试一遍
String token = JwtUtil.createToken(1L);
System.out.println(JwtUtil.verifyToken(token));          // 期望 1
System.out.println(JwtUtil.verifyToken(token + "x"));    // 篡改 -> 期望 null
System.out.println(JwtUtil.verifyToken(""));             // 空串 -> 期望 null
System.out.println(JwtUtil.verifyToken(null));           // null -> 期望 null
```

> **通用教训**：`catch (Exception e) { return null; }` 这种"安全兜底"会把
> `ClassCastException`、`NullPointerException` 这类**代码 bug** 一起吞掉，
> 表现成"功能静默失效"而不是"报错"。写兜底 catch 时，
> 要么至少 `e.printStackTrace()`，要么在返回前记一条日志。

| 一定要自测的 4 种 token | 期望 |
|------------------------|------|
| 正常 token | 返回 userId |
| 签名被篡改 | `null` |
| 已过期 | `null` ← **只写 `verify()` 这里会挂** |
| 空串 / null / 乱字符串 | `null` |

```java
package com.smarthome.config;

import com.smarthome.common.JwtUtil;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.web.servlet.HandlerInterceptor;

public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        Long userId = JwtUtil.verifyToken(request.getHeader("token"));
        if (userId == null) {
            response.setContentType("application/json;charset=utf-8");
            response.getWriter().write("{\"code\":401,\"msg\":\"请先登录\"}");
            return false;                     // 拦截，不进入 Controller
        }
        // 把 userId 挂到 request 上，控制层随取随用，业务层完全不感知 HTTP
        request.setAttribute("userId", userId);
        return true;
    }
}
```

```java
package com.smarthome.service.impl;

import cn.hutool.crypto.digest.BCrypt;
import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.smarthome.common.BizException;
import com.smarthome.common.JwtUtil;
import com.smarthome.entity.Orders;
import com.smarthome.entity.User;
import com.smarthome.mapper.DeviceMapper;
import com.smarthome.mapper.OrderMapper;
import com.smarthome.mapper.UserMapper;
import com.smarthome.service.UserService;
import com.smarthome.vo.UserInfoVO;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final DeviceMapper deviceMapper;
    private final OrderMapper orderMapper;

    @Override
    public void register(String username, String nickname, String password) {
        Long exists = userMapper.selectCount(
                new LambdaQueryWrapper<User>().eq(User::getUsername, username));
        if (exists > 0) throw new BizException("该账号已被注册");

        User user = new User();
        user.setUsername(username);
        user.setPassword(BCrypt.hashpw(password));       // 永远不要存明文密码
        user.setNickname(nickname == null || nickname.isEmpty() ? username : nickname);
        userMapper.insert(user);
    }

    @Override
    public String login(String username, String password) {
        User user = userMapper.selectOne(
                new LambdaQueryWrapper<User>().eq(User::getUsername, username));
        // 账号不存在与密码错误返回同一提示，避免暴露账号是否注册
        if (user == null || !BCrypt.checkpw(password, user.getPassword())) {
            throw new BizException("账号或密码错误");
        }
        return JwtUtil.createToken(user.getId());
    }

    @Override
    public UserInfoVO info(Long userId) {
        User user = userMapper.selectById(userId);
        if (user == null) throw new BizException("用户不存在");

        UserInfoVO vo = new UserInfoVO();
        vo.setId(user.getId());
        vo.setUsername(user.getUsername());
        vo.setNickname(user.getNickname());
        vo.setAvatar(user.getAvatar());
        // 统计类数据在业务层算好，前端直接用
        vo.setDeviceCount(Math.toIntExact(deviceMapper.selectCount(null)));
        vo.setOrderCount(Math.toIntExact(orderMapper.selectCount(
                new LambdaQueryWrapper<Orders>().eq(Orders::getUserId, userId))));
        return vo;
    }
}
```

```java
    /**
```

```java
            RoomEnvironmentVO envVO = toEnvVO(room, env);

            totalAlarm += envVO.getAlarmCount();

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void add(DeviceAddDTO dto, Long userId) {
        checkRoomOwner(dto.getRoomId(), userId);

        Device device = new Device();
        device.setRoomId(dto.getRoomId());
        device.setName(dto.getName());
        device.setType(dto.getType());
        device.setOnline(1);
        // 不同类型设备初始状态不同（2026-09 起共 6 种类型）
        if ("light".equals(dto.getType())) {
            // colorTemp：色温 K 值（2700 暖光 ~ 6500 冷光）

            // mode: cool/heat/dehumidify/fan；fanSpeed: 0 自动 1 低 2 中 3 高；swing: 1 扫风开
            device.setStatus("{\"power\":\"off\",\"temperature\":26,\"mode\":\"cool\",\"fanSpeed\":2,\"swing\":0}");
        } else if ("curtain".equals(dto.getType())) {
            device.setStatus("{\"openPercent\":0}");
        } else if ("pump".equals(dto.getType())) {
            // 水泵（浇花）：watering 是否抽水 0/1；duration 本次浇水分钟数；
            // waterLevel 水箱剩余 %；waterPlan 每日定时 "HH:mm"（空串=不定时）；

            // 门禁（智能门锁）：locked 1 上锁 / 0 开锁（与 power **反向**联动）；
            // battery 电量 %；lastUser / lastTime 最近一次开关门
            device.setStatus("{\"power\":\"off\",\"locked\":1,\"battery\":92,"
                    + "\"lastUser\":\"\",\"lastTime\":\"\"}");

            device.setStatus("{\"power\":\"off\"}");

    }

    /**
     * 定时模拟全屋环境采样（每 30 秒一次，由 SensorSimTask 调用）。
     * 每个房间的 5 项基础指标小幅波动，厨房额外模拟燃气浓度；超阈值自动置报警位。
     * **控制台每个房间打一行**，演示时能看到数值在动。
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void simulateSensors() {
        // 全屋所有房间（不区分用户，模拟的是"物理世界的空气"）
        List<Room> rooms = roomMapper.selectList(new LambdaQueryWrapper<Room>().orderByAsc(Room::getId));
        if (rooms.isEmpty()) {
            log.info("[环境监测] 定时采样：暂无房间，跳过");
            return;
        }
        Random random = new Random();
        int alarmTotal = 0;
        for (Room room : rooms) {
            RoomEnvironment env = loadOrInit(room);
            drift(env, random, room);          // 数值小幅波动
            judgeAlarms(env);                  // 重新判定报警位
            env.setUpdateTime(LocalDateTime.now());
            roomEnvironmentMapper.updateById(env);
            alarmTotal += alarmCountOf(env);

            // ↓↓↓ 演示要点：每个房间在控制台打一行，厨房多打印燃气浓度
            log.info("[环境监测] 定时采样｜房间#{}-{} 温度{}℃ 湿度{}% AQI{} CO₂{}ppm 烟雾{}ppm{} {}",
                    room.getId(), room.getName(), env.getTemperature(), env.getHumidity(),
                    env.getAqi(), env.getCo2(), env.getSmoke(),
                    env.getHasGas() != null && env.getHasGas() == 1 ? " 燃气" + env.getGas() + "ppm" : "",
                    alarmCountOf(env) > 0 ? "⚠ 有告警" : "");
        }
        log.info("[环境监测] 定时采样完成：共 {} 个房间，当前告警 {} 项", rooms.size(), alarmTotal);
    }

    /**
     * 查单个房间的环境监测数据（前端切房间 / 进详情用）。

                room.getId(), room.getName(), env.getTemperature(), env.getHumidity(),

    /**
     * 手动刷新环境：先对未指定的指标做一次小幅随机波动（= 手动触发一次采样），
     * 再把 dto 里显式指定的值覆盖上去（= 演示注入，可以一键造出报警效果）。
     *
     * 【两种用法】
     *  - `POST .../refresh` 空 body        → 只采样（数值小幅波动）
     *  - `POST .../refresh {"gas": 350}`   → 把燃气直接改成 350，立刻触发泄漏告警
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public RoomEnvironmentVO refreshEnvironment(Long roomId, Long userId, RoomEnvDTO dto) {
        Room room = checkRoomOwner(roomId, userId);
        RoomEnvironment env = loadOrInit(room);

        drift(env, new Random(), room);     // 1) 未指定的指标先抖一下

        // 2) 指定了的值直接覆盖（演示注入），顺便记下"注入了什么"用于打印
        StringBuilder injected = new StringBuilder();
        if (dto != null) {
            if (dto.getSmoke() != null) { env.setSmoke(dto.getSmoke()); injected.append("烟雾=").append(dto.getSmoke()).append(" "); }
            if (dto.getGas() != null) { env.setGas(dto.getGas()); injected.append("燃气=").append(dto.getGas()).append(" "); }
            // …temperature / humidity / aqi / co2 / hasGas 同理，略
        }

        clamp(env);                 // 数值夹到合理区间，防止演示时填出 -999 这种脏数据
        judgeAlarms(env);           // 重新判定报警位
        env.setUpdateTime(LocalDateTime.now());
        roomEnvironmentMapper.updateById(env);

        RoomEnvironmentVO vo = toEnvVO(env);
        vo.setRoomName(room.getName());
        // ↓↓↓ 演示要点：谁、在哪个房间、注入/刷新了什么、结果如何
        log.info("[环境监测] 手动刷新｜房间#{}-{} 操作人#{} 注入[{}] → 温度{}℃ 湿度{}% AQI{} CO₂{}ppm 烟雾{}ppm{} 报警{}项",
                room.getId(), room.getName(), userId, injected.toString().trim(),
                vo.getTemperature(), vo.getHumidity(), vo.getAqi(), vo.getCo2(), vo.getSmoke(),
                vo.getHasGas() != null && vo.getHasGas() == 1 ? " 燃气" + vo.getGas() + "ppm" : "",
                vo.getAlarmCount());
        return vo;
    }

    // ---------- 环境监测私有辅助：初始化 / 波动 / 判定 / 转换 ----------

    /**
     * 取房间的环境记录，没有就按房间名初始化一条。
     * 房间名含"厨房/厨/燃气/灶"时自动开启燃气检测（hasGas=1）。
     */
    private RoomEnvironment loadOrInit(Room room) {
        RoomEnvironment env = roomEnvironmentMapper.selectOne(
                new LambdaQueryWrapper<RoomEnvironment>().eq(RoomEnvironment::getRoomId, room.getId()));
        if (env != null) {
            // 老房间后续改名为"厨房"也能自动补上燃气检测
            if (needsGas(room) && (env.getHasGas() == null || env.getHasGas() == 0)) {
                env.setHasGas(1);
                env.setGas(env.getGas() == null ? 20 : env.getGas());
                roomEnvironmentMapper.updateById(env);
            }
            return env;
        }
        env = new RoomEnvironment();
        env.setRoomId(room.getId());
        env.setTemperature(26.0);
        env.setHumidity(58);
        env.setAqi(45);
        env.setCo2(620);
        env.setSmoke(3);
        env.setHasGas(needsGas(room) ? 1 : 0);
        env.setGas(env.getHasGas() == 1 ? 20 : 0);   // 燃气浓度正常状态 0~100 ppm
        env.setSmokeAlarm(0);
        env.setGasAlarm(0);
        env.setUpdateTime(LocalDateTime.now());
        roomEnvironmentMapper.insert(env);
        log.info("[环境监测] 初始化房间环境｜房间#{}-{} 燃气检测={}", room.getId(), room.getName(),
                env.getHasGas() == 1 ? "开启" : "关闭");
        return env;
    }

    /** 房间是否需要燃气检测：房间名命中关键字（厨房 / 厨 / 燃气 / 灶） */
    private boolean needsGas(Room room) {
        String name = room.getName() == null ? "" : room.getName();
        return GAS_ROOM_KEYS.stream().anyMatch(name::contains);
    }

    /** 按阈值判定报警位（烟雾 / 燃气），业务层唯一判定入口 */
    private void judgeAlarms(RoomEnvironment env) {
        env.setSmokeAlarm(env.getSmoke() != null && env.getSmoke() > SMOKE_ALARM ? 1 : 0);
        env.setGasAlarm(env.getHasGas() != null && env.getHasGas() == 1
                && env.getGas() != null && env.getGas() > GAS_ALARM ? 1 : 0);
    }

    /** 单条环境记录的告警项数量：烟雾 / 燃气 / CO₂ / AQI 四项 */
    private int alarmCountOf(RoomEnvironment env) {
        int n = 0;
        if (env.getSmokeAlarm() != null && env.getSmokeAlarm() == 1) n++;
        if (env.getGasAlarm() != null && env.getGasAlarm() == 1) n++;
        if (env.getCo2() != null && env.getCo2() > CO2_ALARM) n++;
        if (env.getAqi() != null && env.getAqi() > AQI_ALARM) n++;
        return n;
    }

    /**
     * entity → VO：把原始数值翻译成"人能看懂"的等级文案。
     * 前端只负责显示，不重复维护阈值口径（改阈值只改这一个文件）。
     */
    private RoomEnvironmentVO toEnvVO(RoomEnvironment env) {
        RoomEnvironmentVO vo = new RoomEnvironmentVO();
        vo.setRoomId(env.getRoomId());
        vo.setTemperature(env.getTemperature());
        vo.setTemperatureLevel(tempLevel(env.getTemperature()));
        vo.setHumidity(env.getHumidity());
        vo.setHumidityLevel(humidityLevel(env.getHumidity()));
        vo.setAqi(env.getAqi());
        vo.setAirLevel(airLevel(env.getAqi()));
        vo.setCo2(env.getCo2());
        vo.setCo2Level(co2Level(env.getCo2()));
        vo.setSmoke(env.getSmoke());
        vo.setSmokeAlarm(env.getSmokeAlarm());
        vo.setHasGas(env.getHasGas());
        // ⭐ 不检测燃气的房间**不给**燃气数值（null），前端据 hasGas 决定要不要渲染这一项
        vo.setGas(env.getHasGas() != null && env.getHasGas() == 1 ? env.getGas() : null);
        vo.setGasAlarm(env.getHasGas() != null && env.getHasGas() == 1 ? env.getGasAlarm() : 0);
        vo.setAlarmCount(alarmCountOf(env));
        vo.setUpdateTime(env.getUpdateTime() == null ? "" : env.getUpdateTime().format(TIME_FMT));
        return vo;
    }

    // ---------- 私有辅助方法：业务规则集中在业务层 ----------

    /** 校验房间归属，实现数据隔离；返回房间对象方便调用方复用（环境模块要用房间名判厨房） */
    private Room checkRoomOwner(Long roomId, Long userId) {
        Room room = roomMapper.selectById(roomId);
        if (room == null) throw new BizException("房间不存在");
        if (!room.getUserId().equals(userId)) throw new BizException("无权操作该房间");
        return room;
    }

    private DeviceVO toVO(Device device) {
        DeviceVO vo = new DeviceVO();
        vo.setId(device.getId());
        vo.setRoomId(device.getRoomId());
        vo.setName(device.getName());
        vo.setType(device.getType());
        vo.setOnline(device.getOnline());
        vo.setStatus(JSONUtil.parseObj(device.getStatus()));
        return vo;
    }
}
```

### 4.6 环境监测模块（2026-09 新增核心）

这是本模块最需要讲清楚的部分，因为涉及一次**架构层面的取舍**。

**为什么环境监测要单独建表？**

| 旧做法（已废弃） | 现做法 |
|------------------|--------|
| 取房间内第一台 `temp_sensor` 设备，读它 `status` JSON 里的温湿度 | 每个房间一条 `room_environment` 记录 |
| 用户删掉温湿度计 → 环境数据整个消失 | 环境数据与设备完全解耦，删设备不影响 |
| 想加"空气质量 / CO₂ / 烟雾 / 燃气"就得往 JSON 里塞更多 key | 都是强类型字段，阈值判定直接算 |
| 要新建"温湿度计"这种假设备充数 | 房间建好就自动补一条环境记录（`loadOrInit`） |

**数据流转：**

```text
SensorSimTask（30 秒）
        ↓ 调业务层
DeviceServiceImpl.simulateSensors()
        ↓ 遍历所有房间
loadOrInit(room) → drift(...) → judgeAlarms(...) → updateById(...)
        ↓                                              ↓
  没有记录就初始化一条                        [环境监测] 定时采样｜房间#3-厨房 …
        ↓
用户打开首页 → GET /api/home/overview → HomeOverviewVO.environments
        ↓
前端 EnvironmentPanel 渲染 5 项（厨房 6 项）
```

**四条设计约定（改代码前必须知道）：**

1. **厨房判定只在后端做一次**：`GAS_ROOM_KEYS = ["厨房", "厨", "燃气", "灶"]`，
   房间名命中就 `hasGas=1`。前端**只认 `hasGas` 字段**，绝不自己判断房间名。
   `loadOrInit` 里还处理了"老房间后来改名叫厨房"的情况，会自动补上燃气检测。

2. **非厨房房间不返回燃气数值**：`toEnvVO` 里 `vo.setGas(hasGas==1 ? gas : null)`。
   **返回 `null` 而不是 `0`** —— 让前端能明确区分"这里没有燃气这项"和"有但浓度为 0"。

3. **阈值口径只在后端维护**：

   | 指标 | 报警阈值 | 常量 | 等级文案 |
   |------|---------|------|---------|
   | 烟雾 | > 50 ppm | `SMOKE_ALARM` | 正常 / ⚠ 烟雾报警 |
   | 燃气 | > 200 ppm | `GAS_ALARM` | 正常 / ⚠ 燃气泄漏 |
   | 二氧化碳 | > 1500 ppm | `CO2_ALARM` | 清新 / 正常 / 偏高·建议通风 / 闷浊·请立即通风 |
   | 空气质量 | > 150 | `AQI_ALARM` | 优 / 良 / 轻度污染 / 中重度污染 |
   | 温度 | <18 或 >28 ℃ | —（仅 UI 上色） | 偏冷 / 舒适 / 偏热 |
   | 湿度 | <30 或 >70 % | —（仅 UI 上色） | 干燥 / 舒适 / 潮湿 |

   VO 里带回 `temperatureLevel` / `airLevel` / `co2Level` 等中文等级，
   **前端只显示、不重算**。以后要调阈值，只改 `DeviceServiceImpl` 一个文件。

4. **数值夹紧（clamp）**：演示时 `refresh` 传 `-999` 也不会写进脏数据 ——
   温度夹到 `-10~50`、湿度 `10~100`、AQI `0~500`、CO₂ `350~5000`、
   烟雾 `0~999`、燃气 `0~9999`。

**演示注入式刷新（答辩/验收时的核心演示点）：**

```bash
# 空 body：只做一次小幅随机波动（= 立即采样一次）

  -H "token: <JWT>" -H "Content-Type: application/json" -d '{}'

# 传字段：直接覆盖成该值 —— 一键造出"烟雾报警"效果
curl -X POST http://localhost:8080/api/room/1/environment/refresh \
  -H "token: <JWT>" -H "Content-Type: application/json" -d '{"smoke":180}'

# 厨房燃气泄漏：改 gas 就能触发（room 3 是厨房，hasGas=1）

```

> ⚠️ 刷新接口是 **`@RequestBody(required = false)`** —— 空 body 必须能跑通，
> 忘了加 `required = false` 会在空 body 时直接 400。

**新增房间时的初始化**：`loadOrInit()` 会在首次访问时插入一条默认记录
（26℃ / 58% / AQI 45 / CO₂ 620ppm / 烟雾 3ppm）。
所以 `init_all.sql` 里的 `room_environment` 数据只是"演示初始值"，不是必需依赖 ——
用户新建房间也能立刻看到环境面板有数据。

```java
package com.smarthome.service.impl;

import cn.hutool.json.JSONUtil;
import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.smarthome.common.BizException;
import com.smarthome.entity.Scene;
import com.smarthome.entity.SceneAction;
import com.smarthome.mapper.SceneActionMapper;
import com.smarthome.mapper.SceneMapper;
import com.smarthome.service.DeviceService;
import com.smarthome.service.SceneService;
import com.smarthome.vo.SceneVO;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

@Service
@RequiredArgsConstructor
public class SceneServiceImpl implements SceneService {

    private final SceneMapper sceneMapper;
    private final SceneActionMapper sceneActionMapper;
    private final DeviceService deviceService;      // 复用设备控制逻辑，不重复写

    @Override
    public List<SceneVO> list(Long userId, String triggerType) {
        LambdaQueryWrapper<Scene> wrapper = new LambdaQueryWrapper<Scene>()
                .eq(Scene::getUserId, userId)
                .orderByAsc(Scene::getId);
        if (triggerType != null && !triggerType.isEmpty()) {
            wrapper.eq(Scene::getTriggerType, triggerType);
        }
        return sceneMapper.selectList(wrapper).stream().map(this::toVO).collect(Collectors.toList());
    }

    /**
     * 一键执行场景：把场景里的每个动作依次下发给对应设备。
     * 加了事务：要么全部生效，要么全部回滚，避免"执行到一半"的脏状态。
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void run(Long sceneId, Long userId) {
        Scene scene = sceneMapper.selectById(sceneId);
        if (scene == null) throw new BizException("场景不存在");
        if (!scene.getUserId().equals(userId)) throw new BizException("无权执行该场景");

        List<SceneAction> actions = sceneActionMapper.selectList(
                new LambdaQueryWrapper<SceneAction>().eq(SceneAction::getSceneId, sceneId));
        if (actions.isEmpty()) throw new BizException("该场景还没有配置动作");

        for (SceneAction action : actions) {
            Map<String, Object> actionMap = JSONUtil.parseObj(action.getAction());
            deviceService.control(action.getDeviceId(), userId, actionMap);
        }
    }

    @Override
    public void toggle(Long sceneId, Long userId, Integer enabled) {
        Scene scene = sceneMapper.selectById(sceneId);
        if (scene == null) throw new BizException("场景不存在");
        if (!scene.getUserId().equals(userId)) throw new BizException("无权操作该场景");
        scene.setEnabled(enabled);
        sceneMapper.updateById(scene);
    }

    /** 定时任务调用：每分钟检查一次，到点的自动化就执行 */
    @Override
    public void runTimedScenes() {
        List<Scene> timedScenes = sceneMapper.selectList(new LambdaQueryWrapper<Scene>()
                .eq(Scene::getTriggerType, "TIMER")
                .eq(Scene::getEnabled, 1));

        String now = LocalTime.now().format(DateTimeFormatter.ofPattern("HH:mm"));
        for (Scene scene : timedScenes) {
            if (now.equals(scene.getCronExpr())) {      // cron_expr 存 "HH:mm"，够 Demo 用
                try {
                    run(scene.getId(), scene.getUserId());
                } catch (Exception e) {
                    // 单个场景失败不影响其他场景
                    System.err.println("场景执行失败：" + scene.getName() + "，" + e.getMessage());
                }
            }
        }
    }

    private SceneVO toVO(Scene scene) {
        SceneVO vo = new SceneVO();
        vo.setId(scene.getId());
        vo.setName(scene.getName());
        vo.setIcon(scene.getIcon());
        vo.setTriggerType(scene.getTriggerType());
        vo.setCronExpr(scene.getCronExpr());
        vo.setEnabled(scene.getEnabled());
        return vo;
    }
}
```

```java
package com.smarthome.task;

import com.smarthome.service.DeviceService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

@Slf4j
@Component
@RequiredArgsConstructor
public class WaterTimedTask {

    private final DeviceService deviceService;

    /**
     * 每分钟的第 0 秒执行一次（与 SceneTimedTask 同频，但互不影响）。
     * 顺序很重要：先看要不要开泵，再看要不要停泵 —— 这样"到点开、到点停"不会在同一次扫描里打架。
     */
    @Scheduled(cron = "0 * * * * ?")
    public void scanWatering() {
        try {
            int fired = deviceService.runTimedWatering();   // 到点自动开泵
            int stopped = deviceService.tickWatering();     // 到点自动停泵 + 扣水量
            // 只在真有动作时打一行汇总，避免每分钟刷屏（没有水泵设备时一行都不打）
            if (fired > 0 || stopped > 0) {
                log.info("[定时浇水] 本轮扫描完成：自动开泵 {} 台，自动停泵 {} 台", fired, stopped);
            }
        } catch (Exception e) {
            // 定时任务里抛异常会静默终止后续调度，这里兜住并打出来，方便排查
            log.error("[定时浇水] 扫描异常：{}", e.getMessage(), e);
        }
    }
}
```

> **为什么用"每分钟扫一遍"，而不是 `Timer` / `ScheduledExecutorService` 延时线程？**
>
> ① 项目只跑一个后端实例，每分钟扫一遍最简单、最直观，组员看代码一眼就懂；
> ② 状态全在 `device.status` JSON 里，**重启进程也不会丢**——重启后下一分钟接着扫就行，
> 而延时线程一重启任务就没了；
> ③ 与 `SceneTimedTask` 完全同构，不用多学一套 API。
>
> **两个配套的业务方法**（都在 `DeviceServiceImpl`）：
>
> | 方法 | 干什么 | 什么时候返回非 0 |
> |------|--------|-----------------|
> | `runTimedWatering()` | 找出 `waterPlan` 等于当前 `HH:mm`、且没在浇水的泵 → `control()` 开泵 | 返回本次开泵台数 |
> | `tickWatering()` | 在浇水的泵：先把水位推进到当前（`开浇水位 − 已浇分钟数`，1%/分钟，封底 0），到 `waterEndTime` 的再停泵 | 返回本次停泵台数 |
>
> **一个容易忽略的兜底**：`tickWatering()` 里如果读到 `waterEndTime` 解析不出来（老数据/脏数据），
> 会**补写一个** `now + duration` 的结束时间，而不是跳过 —— 否则水泵会永远停不下来。
>
> **水量为什么不由接口直接设（2026-09 修正）**：水箱水量是**消耗属性**，不是可控属性。
> 开泵时 `startWatering()` 记下 `waterStartLevel` / `waterStartTime`，之后由
> `syncWaterLevel()` 按"开浇水位 − 已浇分钟数"**幂等推算**剩余水量 ——
> 不是"每跑一次扣一格"，所以定时任务重复执行、多跑几次都不会多扣水。
> `control()` 里对水泵会**丢掉指令中的 `waterLevel`**，防止前端把水箱凭空加满
> （前端详情页也换成了只读进度条，不给滑杆）。
>
> **定时任务节拍导致的"延迟"是正常的**：cron 是 `0 * * * * ?`，只在每分钟第 0 秒跑，
> 所以停泵发生在到点后的第一个整分，最晚比 `waterEndTime` 晚约 60 秒。
> 验证时别只等 `duration` 那么久，要**多等一个整分周期**（浇 1 分钟 → 等 2 分钟以上）。
>
> **控制台打印**（演示时能直接看到水泵在动）：
> `[定时浇水] 定时触发｜设备#7-阳台浇花水泵 计划07:00 水箱剩余80% → 自动开泵 10 分钟`、
> `[定时浇水] 自动停泵｜设备#7-阳台浇花水泵 浇水10分钟 水箱剩余70%`、
> `[定时浇水] 手动浇水｜设备#7-阳台浇花水泵 时长5分钟，水箱剩余80%`。

**核心设计：把"开 / 关"翻译成各类型自己的语义字段**

定时本身只有两个终点，落到不同设备上却是不同字段 —— 映射收敛在 `applyTimer()` 一个方法里：

| 设备类型 | 定时"开"（`timerOn` 到点） | 定时"关"（`timerOff` 到点） |
|---------|--------------------------|---------------------------|
| light / ac / socket | `power = on` | `power = off` |
| curtain | `openPercent = 100` | `openPercent = 0` |
| pump | `watering = 1`（按 `duration`） | `watering = 0`（结清水量后停） |
| lock | `locked = 0`（开锁） | `locked = 1`（上锁） |

> **为什么不做成"每种设备一个定时任务"**：那会变成 6 个几乎一样的类，加新设备类型还得再抄一遍。
> 收敛成一个方法后，新类型只补一行映射。
>
> **幂等性**：判断条件是 `now.format("HH:mm").equals(timerOn)`，本任务每分钟只跑一次，
> 同一分钟不会被重复触发。到点执行后**不清空字段**（每天重复），符合"每天 7 点开灯"的直觉。
>
> **两个定时撞在同一分钟**：**关机优先**（`turnOn = onDue && !offDue`）—— 关比开安全。
>
> **日志会区分来源**：定时触发写「定时开机：…」/「定时关机：…」，
> 用户手动控制写「控制：…」，演示时一眼能看出这条是谁干的。
> （设备表本身不存 `userId`，日志里的用户取自该设备所属房间的主人。）

**插座计量为什么也放这个任务里**：用电量是时间的函数 ——
只在用户点开关那一下算一次，通电期间消耗的电就全丢了。
所以每分钟把 `ratedW / 60.0 / 1000.0` 累加进 `energyKwh`，断电时把 `powerW` 归零。

> **控制台打印**：`[设备定时] 定时开机｜设备#2-客厅空调(ac) 到点14:26 → 新状态{...}`。
> 验证脚本见 `.scan/device_func_verify.py`（含"设成下一分钟并真等到点"的用例）。

```java
            item.setGoodsId(goodsId);
```

```java
            Goods goods = goodsMapper.selectById(goodsId);
            if (goods == null) throw new BizException("商品不存在");
            if (goods.getStock() < quantity) throw new BizException(goods.getName() + " 库存不足");

            // 扣库存、加销量
            goods.setStock(goods.getStock() - quantity);
            goods.setSales(goods.getSales() + quantity);
            goodsMapper.updateById(goods);

            // 订单项保存商品快照：以后商品改价/下架，历史订单显示仍然正确
            OrderItem orderItem = new OrderItem();
            orderItem.setGoodsId(goodsId);
            orderItem.setGoodsName(goods.getName());
            orderItem.setGoodsCover(goods.getCover());
            orderItem.setPrice(goods.getPrice());
            orderItem.setQuantity(quantity);
            orderItems.add(orderItem);

            total = total.add(goods.getPrice().multiply(BigDecimal.valueOf(quantity)));
        }

        // 生成订单主表
        Orders order = new Orders();
        order.setOrderNo(generateOrderNo());
        order.setUserId(userId);
        order.setAddressId(addressId);
        order.setTotalAmount(total);
        order.setStatus(0);                          // 0 待付款
        order.setCreateTime(LocalDateTime.now());
        orderMapper.insert(order);

        // 生成订单项（此时才有 orderId）
        for (OrderItem orderItem : orderItems) {
            orderItem.setOrderId(order.getId());
            orderItemMapper.insert(orderItem);
        }

        // 清掉购物车里已下单的商品
        List<Long> goodsIds = orderItems.stream().map(OrderItem::getGoodsId).toList();
        cartItemMapper.delete(new LambdaQueryWrapper<CartItem>()
                .eq(CartItem::getUserId, userId)
                .in(CartItem::getGoodsId, goodsIds));

        return detail(order.getId(), userId);
    }

    /**
     * 模拟支付：真实项目这里等支付平台回调，
     * Demo 直接把状态改为"已付款"，让整条链路能演示完整。
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void pay(Long orderId, Long userId) {
        Orders order = orderMapper.selectById(orderId);
        if (order == null || !order.getUserId().equals(userId)) throw new BizException("订单不存在");
        if (order.getStatus() != 0) throw new BizException("该订单当前状态不可支付");

        order.setStatus(1);                          // 1 已付款
        order.setPayTime(LocalDateTime.now());
        orderMapper.updateById(order);
    }

    /** 取消订单：把库存加回去，保证数据一致 */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void cancel(Long orderId, Long userId) {
        Orders order = orderMapper.selectById(orderId);
        if (order == null || !order.getUserId().equals(userId)) throw new BizException("订单不存在");
        if (order.getStatus() != 0) throw new BizException("已付款订单不能取消");

        List<OrderItem> items = orderItemMapper.selectList(
                new LambdaQueryWrapper<OrderItem>().eq(OrderItem::getOrderId, orderId));
        for (OrderItem item : items) {
            Goods goods = goodsMapper.selectById(item.getGoodsId());
            if (goods != null) {
                goods.setStock(goods.getStock() + item.getQuantity());
                goodsMapper.updateById(goods);
            }
        }
        order.setStatus(3);                          // 3 已取消
        orderMapper.updateById(order);
    }

    @Override
    public List<OrderVO> list(Long userId, Integer status) {
        LambdaQueryWrapper<Orders> wrapper = new LambdaQueryWrapper<Orders>()
                .eq(Orders::getUserId, userId)
                .orderByDesc(Orders::getCreateTime);
        if (status != null && status >= 0) {         // -1 表示全部
            wrapper.eq(Orders::getStatus, status);
        }
        List<OrderVO> result = new ArrayList<>();
        for (Orders order : orderMapper.selectList(wrapper)) {
            result.add(detail(order.getId(), userId));
        }
        return result;
    }

    @Override
    public OrderVO detail(Long orderId, Long userId) {
        Orders order = orderMapper.selectById(orderId);
        if (order == null) throw new BizException("订单不存在");
        if (!order.getUserId().equals(userId)) throw new BizException("无权查看该订单");

        OrderVO vo = new OrderVO();
        vo.setId(order.getId());
        vo.setOrderNo(order.getOrderNo());
        vo.setTotalAmount(order.getTotalAmount());
        vo.setStatus(order.getStatus());
        vo.setCreateTime(order.getCreateTime());
        vo.setItems(orderItemMapper.selectList(
                new LambdaQueryWrapper<OrderItem>().eq(OrderItem::getOrderId, orderId)));
        return vo;
    }

    /** 订单号：时间戳 + 3 位随机数 */
    private String generateOrderNo() {
        String time = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHHmmss"));
        int random = new Random().nextInt(900) + 100;
        return time + random;
    }
}
```

> 第三类绕的人最多，遇到"改了没用"直接跳过去看。

### 10.1 A 类：启动不了

| 现象 | 原因与解决 |
|------|-----------|
| `Access denied for user 'root'@'localhost' (using password: YES)` | 三个可能：① `application.yml` 里还是占位符文字；② 密码写错了；③ 密码含 `# @ ! :` 没加双引号。详见 1.4 节 |
| 改了密码**还是** `Access denied` | 见 **10.3 节**——多半是没保存或 `target/classes` 是旧副本，不是密码的问题 |
| `Unknown database 'smart_home'` | 没导入脚本。跑一遍 `init_all.sql` 即可，它自带建库语句（导入方法见 10.4） |
| `Communications link failure` | MySQL 服务没启动。`Win+R` → `services.msc` → 找到 MySQL80 → 启动 |
| `Port 8080 was already in use` | 已经有一个后端实例在跑，或别的程序占了 8080。`netstat -ano \| findstr :8080` 查 PID 后结束进程。**注意项目有定时任务，绝不能同时跑两个实例**（见 1.6 节） |
| 启动日志一大片红色不知道看哪行 | **只看两处**：第一行 `ERROR`（谁抛的）+ **`Caused by:`**（真正原因）。`at org.springframework...` 那些只是调用栈 |
| 日志显示 `Started SmartHomeApplication` 但接口报 500 | **正常现象**。连接池是懒加载的，`Started` 不代表数据库已连通。往上翻第一条 `Caused by` |
| 命令行 `mvnw.cmd` 找不到 | Maven Wrapper（`mvnw` / `mvnw.cmd` / `.mvn/`）不在工程根目录。确认它们在 `smarthome_server` 下（早期清理连字符目录时被误搬走过） |
| `mvnw.cmd` 报 `The JAVA_HOME environment variable is not defined correctly` | 系统里 `JAVA_HOME` 指向的目录不存在或不含 `bin\java.exe`。**先确认路径真实存在**：`dir %JAVA_HOME%\bin\java.exe`。本机实际 JDK 在 `D:\Soft\Java\jdk-17.0.18`，而 `JAVA_HOME` 却指向一个不存在的目录——IDEA 用自己的 SDK 配置所以照常能跑，只有命令行会挂。临时用：`set JAVA_HOME=D:\Soft\Java\jdk-17.0.18`（或在系统环境变量里改对） |

### 10.2 B 类：接口不对

| 现象 | 原因与解决 |
|------|-----------|
| 接口返回 401 | 按这个顺序查：① **进程是不是旧的没重启**（见 1.7，本项目第一高频原因）② 请求头没带 `token`（名字就叫 `token`，不是 `Authorization`）③ token 真过期（默认 7 天） |
| **登录接口返回 200 和 token，但之后所有需要登录的接口全 401** | 先排除 1.7 的"进程没重启"，排除不掉再查代码：`JwtUtil.verifyToken` 里 `getPayload("userId")` 强转 `Integer` 会抛 `ClassCastException`（Hutool 5.8.x 返回的是 `NumberWithFormat`），又被 `catch` 吞掉 → 返回 `null` → 拦截器判定未登录。控制台**一行报错都没有**，所以特别难查。见 2.4 节坑 2 |
| 过期 token 依然能通过鉴权 | `JWT.verify()` 只验签名不验有效期，要改用 `validate(0)`。见 2.4 节坑 1 |
| 前端提示"登录已过期，请重新登录"，但 token 明明是刚生成的 | 同上两条，先照 2.4 节的自测清单把 4 种 token 跑一遍 |
| 前端拿到的设备状态是字符串 | `DeviceVO.status` 应是 `JSONObject` 而不是 `String`，检查 `toVO()` 里有没有 `JSONUtil.parseObj()` |
| 时间显示成 `2024-01-01T10:00:00` | Jackson 没配 `date-format`，检查 yml（1.4 节） |
| 环境数值不变 | 启动类没加 `@EnableScheduling`（详见 1.2 节）。注意：**与环境数值无关的设备已不再是判据**——`simulateSensors()` 遍历的是"所有房间"，不再依赖 `temp_sensor` 设备 |
| 环境数值**跳得比正常快** | 起了两个后端实例，两个定时任务都在跑。见 1.6 节 |
| **厨房面板不显示"燃气泄漏"项** | ① 该房间 `room_environment.has_gas = 0` —— 房间名不含「厨房/厨/燃气/灶」，改房间名后再进一次首页（`loadOrInit` 会自动补 `hasGas=1`）；② 前端在按房间名自己判断，应改为只认 `hasGas` 字段 |
| **刷新环境接口 400** | `@RequestBody` 忘了加 `required = false`，空 body 时 Spring 直接拒绝。见 4.6 节 |
| **`refresh` 传了值但没生效** | 数值被 `clamp()` 夹了。比如传 `temperature: -999`，实际会存成 `-10`。这是刻意设计（防止演示时写脏数据），不是 bug |
| **新建房间后环境面板显示"暂无环境数据"** | 正常情况下 `loadOrInit` 会在首次访问时自动插一条默认记录。若持续为空，检查 `room_environment.room_id` 的唯一索引是否和 `room.id` 对得上 |
| 定时场景不触发 | `cron_expr` 格式必须是 `HH:mm`（如 `23:00`），且 `enabled = 1` |
| 定时场景重复执行 | 同上，多半是有两个实例 |
| 下单报"库存不足" | 正常逻辑，去数据库把 `goods.stock` 调大 |
| 支付报"当前状态不可支付" | 订单已是已付款/已取消状态，属于业务校验，正常 |
| SQL 不打印 | `log-impl` 配置没生效，检查 yml 缩进 |
| 局域网内手机连不上后端 | Windows 防火墙放行 8080 端口：控制面板 → 防火墙 → 入站规则 → 新建规则 |

### 10.3 C 类：改了没生效（绕得最久的一类）

**共同点：不是代码写错了，是"改的东西没被读到"。按顺序排除，别跳步。**

| 现象 | 原因与解决 |
|------|-----------|
| `application.yml` 改了密码，启动还是 `Access denied`，报错一字不差 | ① 编辑器**没保存**（IDEA 标签页 `*` 号没消失）；② 运行期读的是 `target/classes/application.yml` 旧副本。解决：`Ctrl+S` → `type` 源文件确认 → `Ctrl+F9` Rebuild → 重启。详见 1.5 节 |
| 改了 Java 代码，**编译也通过了**，但接口行为一点没变 | ⚠️ **本项目最坑的一条**。Rebuild 只是更新 `target/classes/`，跑着的 JVM 里仍是启动那一刻加载的旧 class。**必须重启进程**（IDEA 点 **⟳ Rerun**，或先 Stop 再 Run）。判断方法见 1.7 节：比对「进程启动时间」和「class 编译时间」，**进程比 class 早就是旧的** |
| 修好的接口仍然返回旧结果 / 一直 401 | 同上，进程没重启。真实案例：`JwtUtil` 修复编译于 **15:46**，而 8080 上跑的进程启动于 **15:26**，所以登录接口正常返回 token、后续接口全 401 |
| 改了 `@Scheduled` 的 cron 表达式没反应 | 定时任务的 cron 在启动时读入，**必须重启进程**才生效 |
| `type` 看到的内容和 IDEA 里显示的不一样 | 说明 IDEA 里那份没落盘。IDEA 会显示内存中的未保存内容，**不要用它来验证文件是否已保存** |
| 找不到自己改的是哪个工程 | 命名不一致会出现 `smarthome_server` / `smarthome-server` **两套目录**。在项目根 `dir /b` 确认，只保留有代码的那一套（见《01_总方案.md》第十一章踩坑 1） |
| 提交后别人拉下来启动不了 | 提交前没验证。**先本地跑通再 commit**；同时确认 `target/`、`.idea/` 没被加进暂存区 |

> **排查口诀：C 类问题的第一步永远是"确认磁盘上的文件真的是新的"。**
> 顺序是：① 保存（看 `*` 号）→ ② `type` 核对磁盘 → ③ Rebuild 同步 `target/classes/`
> → ④ **重启进程**（这一步最容易漏，见 1.7）→ ⑤ 再怀疑代码。
> 跳过前几步直接去清缓存、重装 Maven，只会浪费时间。

### 10.4 附：数据库脚本怎么导入

**项目只有一份 SQL 脚本：`Mysql/init_all.sql`** —— 自包含（建库 + 建表 + 全套演示数据），
可单独交付。无论全新环境还是重置演示数据，**直接执行整个文件即可**，也可以反复执行。

> **演进说明**：这份脚本由早期的"一份建库脚本 + 多个老库增量升级脚本"合并而来，
> 增量内容已全部并入，原文件不再保留 —— 所以不存在"该跑哪一段"的选择题，
> 也没有"两部分互斥、连跑会白建库"的坑。

`mysql -u root -p < Mysql/init_all.sql` 在 **PowerShell 里会失败**——PowerShell 不支持 `<` 重定向。任选一种：

```cmd
:: 1) 用 cmd 包一层 —— ⚠️ 必须带 --default-character-set=utf8mb4，否则中文全变问号
cmd /c "mysql -u root -p --default-character-set=utf8mb4 < Mysql\init_all.sql"

:: 2) 进入 mysql 后用 source（注意路径用正斜杠；先执行 SET NAMES utf8mb4;）
mysql -u root -p
mysql> SET NAMES utf8mb4;
mysql> source D:/Code/smarthome_project/Mysql/init_all.sql

:: 3) Navicat / DataGrip「运行 SQL 文件」（图形界面，最省事；连接编码选 utf8mb4）
```

> ⚠️ **编码不看住，中文全变 `?`**：房间名/设备名/商品名/轮播标题会在入库时丢中文，**不可逆**，只能重新导入。
> 项目里真实踩过这个坑（整库房间、设备、商品、轮播、场景名集体变成问号）。导入后随手确认一下首页有中文。

脚本里的建库语句是 `DROP DATABASE IF EXISTS` + `CREATE DATABASE`，**不用手动新建库，也不用先 `USE`**。

**导入成功的验证**（应能看到 16 张表）：

```cmd
mysql -u root -p -e "use smart_home; show tables;"
```

期望看到：`user`、`address`、`room`、`device`、**`room_environment`**、`device_log`、`scene`、`scene_action`、
`product`、`goods`、`goods_category`、`cart_item`、`orders`、`order_item`、
`operation_log`、`banner`。

数据量核对（四个数都对上就没问题）：

```cmd
mysql -u root -p -e "use smart_home; select count(*) from room; select count(*) from device; select count(*) from room_environment; select count(*) from goods;"
-- 期望：4 / 19 / 4 / 20
```

> **演示账号**：`demo / 123456`（带 **4 个房间**（客厅/卧室/厨房/阳台）、**19 台设备**（覆盖 17 种设备类型）、
> **4 条环境记录**、9 个场景、8 个产品、20 个商品、7 条轮播）。
> 若 demo 登录失败（BCrypt 版本差异），直接注册新账号即可。
